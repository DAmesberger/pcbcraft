## Live MCP

Live MCP into the open window (`crates/automation/src/live.rs`, `apps/pcbcraft/src/app/live_mcp.rs`) uses Solidcraft's control channel, `solidcraft-control` from the pinned fork revision above (MIT OR Apache-2.0), through its public API: the per-session token and its files, the loopback bind and the JSON-lines connection server (`server::Hub`). Nothing was added to Solidcraft for it.

The shape of the feature follows [tangency-labs/pcbcraft](https://github.com/tangency-labs/pcbcraft) (MIT OR Apache-2.0): a socket worker that hands each request to the UI thread, which refuses it while a dialog or a text edit holds the editor, and an opt-in with a configuration to copy, reached from the app. Only the idea was reused, not code or text; the gate, revision checks, refusals and panel here are original and run on Sparksmith's own engine.

## Tone map in the look tests

The PCB 3D look tests (`apps/pcbcraft/src/viewport/pictures/look.rs`, test code only) follow the Khronos PBR Neutral tone mapping specification (Apache-2.0; Copyright The Khronos Group Inc.). They use it to check their own inverse of the tone map, which undoes the viewport's tone map before measuring radiance.

## SVG import

SVG artwork import (`crates/solidcraft-integration/src/svg.rs`) calls Solidcraft's public SVG reader, `solidcraft_engine::io::read_svg` (`crates/io/src/svg.rs` of the pinned fork revision above, unchanged from upstream `4f3ac07`; MIT OR Apache-2.0), for all path, shape, transform and unit handling. The element walk uses [quick-xml](https://github.com/tafia/quick-xml) 0.41 (MIT), the version that reader already depends on. The conversion to Sparksmith graphics and the test fixture `crates/solidcraft-integration/src/svg/mark.svg` are original.

## Polygon operations dependency

Copper fills (`crates/editor-core/src/layout/fill/geom.rs`) compute their boolean operations and offsets with [iOverlay](https://github.com/iShape-Rust/iOverlay) `i_overlay` 9.1 (MIT OR Apache-2.0) and its `i_float`, `i_shape`, `i_tree` and `i_key_sort` crates (MIT), used as Cargo dependencies through their documented public API. Cargo retains upstream notices. The fill algorithm, thermal reliefs, island logic and test fixtures are original.

## Embedded scripting dependency

The scripting feasibility slice embeds [Rhai](https://github.com/rhaiscript/rhai) 1.27.0 (MIT OR Apache-2.0) as a Cargo dependency. Cargo retains upstream notices; the dependency is pinned in the manifest and lockfile. Sparksmith's quantity operations, pad-generation interface and test fixtures are original. The integration uses the documented [custom type](https://rhai.rs/book/rust/custom-types.html), [expression-only](https://rhai.rs/book/engine/expressions.html), [execution limit](https://rhai.rs/book/safety/max-operations.html) and [wasm](https://rhai.rs/book/start/builds/wasm.html) APIs. `wasm-bindgen-test` and its separately installed matching runner provide the optional Node-hosted wasm test execution.
