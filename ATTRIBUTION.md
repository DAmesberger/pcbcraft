# Attribution

## Solidcraft agent instructions

`AGENTS.md`, `CLAUDE.md` and the instructions in `skills/pcbcraft-*/SKILL.md` adapt conventions and guidance from [Solidcraft](https://github.com/tangency-labs/solidcraft/tree/4f3ac07aec69489183185071f07d7fbcf4f51e64), revision `4f3ac07aec69489183185071f07d7fbcf4f51e64`.

Source material includes its `AGENTS.md`, `CLAUDE.md`, and skills for commands, UI, crash safety, file formats, tests, performance and ground rules. The adapted instructions replace Solidcraft-specific workflows and add Pcbcraft's electrical-library, routing, native-model and copper requirements.

## Build conventions and engine dependency

The Cargo development/CI profiles, pinned geometry patches and `xtask` workflow convention are adapted from the same Solidcraft revision under the MIT option above. The implementation of Pcbcraft's commands and checks is original. The desktop links Solidcraft’s UI package and uses its bundled visual assets directly.

Pcbcraft directly depends on `solidcraft-engine`, `solidcraft-ui-egui` and the geometry and windowing patches built from the fork [DAmesberger/solidcraft](https://github.com/DAmesberger/solidcraft/tree/d53b131e3d1cf0b9489e9c048c60af787b14cc47) at revision `d53b131e3d1cf0b9489e9c048c60af787b14cc47` (branch `pcbcraft-via2`): upstream revision `4f3ac07aec69489183185071f07d7fbcf4f51e64` plus an opt-in real-time "product look" for the PCB 3D view (studio environment, clear coats, procedural surface patterns, ambient occlusion and PBR Neutral tone mapping) and via scaling (indexed profile nesting, batched copies and joints, instanced display, deferred evaluation). The desktop turns the look on for its 3D views; Solidcraft's own app does not. The fork's renderer contains Apache-2.0 code adapted from the Khronos PBR Neutral tone mapper (`pbr_neutral`, `look_tone`; Copyright The Khronos Group Inc.); the fork's `NOTICE` carries that attribution and applies to the renderer Pcbcraft builds. The instructions and source adapted below cite upstream revision `4f3ac07` unless they say otherwise; those files are unchanged in the fork. Cargo retrieves the original packages with their upstream license notices; `Cargo.lock` records resolved dependencies. Pcbcraft does not maintain a separate CAD engine or native-file writer. Record further adopted source/assets and their notices here.

Original Pcbcraft code is licensed MIT OR Apache-2.0, like Solidcraft; see [LICENSE-MIT](LICENSE-MIT), [LICENSE-APACHE](LICENSE-APACHE) and [NOTICE](NOTICE). Every workspace crate declares this license, and `cargo xtask licences --check` enforces it together with the dependency license policy.

## SVG import

SVG artwork import (`crates/solidcraft-integration/src/svg.rs`) calls Solidcraft's public SVG reader, `solidcraft_engine::io::read_svg` (`crates/io/src/svg.rs` of the pinned fork revision above, unchanged from upstream `4f3ac07`; MIT OR Apache-2.0), for all path, shape, transform and unit handling. The element walk uses [quick-xml](https://github.com/tafia/quick-xml) 0.41 (MIT), the version that reader already depends on. The conversion to Pcbcraft graphics and the test fixture `crates/solidcraft-integration/src/svg/mark.svg` are original.

## Polygon operations dependency

Copper fills (`crates/editor-core/src/layout/fill/geom.rs`) compute their boolean operations and offsets with [iOverlay](https://github.com/iShape-Rust/iOverlay) `i_overlay` 9.1 (MIT OR Apache-2.0) and its `i_float`, `i_shape`, `i_tree` and `i_key_sort` crates (MIT), used as Cargo dependencies through their documented public API. Cargo retains upstream notices. The fill algorithm, thermal reliefs, island logic and test fixtures are original.

## Embedded scripting dependency

The scripting feasibility slice embeds [Rhai](https://github.com/rhaiscript/rhai) 1.27.0 (MIT OR Apache-2.0) as a Cargo dependency. Cargo retains upstream notices; the dependency is pinned in the manifest and lockfile. Pcbcraft's quantity operations, pad-generation interface and test fixtures are original. The integration uses the documented [custom type](https://rhai.rs/book/rust/custom-types.html), [expression-only](https://rhai.rs/book/engine/expressions.html), [execution limit](https://rhai.rs/book/safety/max-operations.html) and [wasm](https://rhai.rs/book/start/builds/wasm.html) APIs. `wasm-bindgen-test` and its separately installed matching runner provide the optional Node-hosted wasm test execution.
