# Libraries and persistence

Use [GLOSSARY.md](../../GLOSSARY.md) and [part library design](../../docs/part-library-design.md) as the domain reference. Keep electrical definitions, symbol views, packages, footprints, bindings and manufacturer parts distinct even when one UI authors them together.

## Identity and mapping

- Preserve stable definition, terminal, pad and instance identities across renaming and reannotation. Treat a label correction and an electrical remapping as different operations.
- Make mappings explicit and complete. A package terminal belongs to at most one electrical terminal; multiple physical terminals can share electrical intent while retaining independent routing obligations.
- Same-net membership does not establish copper connectivity. Distinguish device-declared NC, project no-connect decisions and non-electrical holes.
- Validate exact manufacturer selections against project requirements. Changing a generic value must surface any incompatible retained MPN.

## Revision updates

Save immutable revisions and snapshot the complete dependency closure, including native 3D models and their parameter interfaces. Required bytes must be available offline; a hash and missing remote URL are not a portable snapshot.

Before applying an update, compute an impact plan tied to the current project revision: changed terminals/nets, pad geometry, affected tracks, mechanical transforms and required assets. Apply as one undoable transaction or leave the old state intact. Preserve valid copper; flag detached tracks and ambiguous remaps instead of silently reconnecting or retagging them.

Make editing scope explicit: project-local definition/selected instances versus source library. Library edits never mutate existing project snapshots automatically.

## File changes

Version persistence explicitly. Test unsupported-version refusal, damaged input and offline reopen. Write atomically through `pcbcraft-io`. Treat renderer caches as disposable, versioned data; retain authoritative parametric definitions.

Pcbcraft is pre-release: `pcbcraft_core::format` accepts only the current version, with no migrations or legacy readers. Add a migration mechanism (and old-file tests) with the first released format; do not refer to nonexistent upstream-style pending folders. A Solidcraft format change follows the actual instructions and migration machinery in the upstream checkout.

Record imported asset provenance/license separately from code licensing. Report unsupported input features without silently changing the electrical meaning. Cover the relevant edge cases from the library proposal through the public command API.

## Clean-room sources

Pcbcraft is MIT OR Apache-2.0. Code under a GPL-family license cannot be adapted into it, and reading such code first makes an "independent" reimplementation hard to defend. Electronics is crowded with GPL-family tools, so name them:

- Do not open, browse, search, copy or paraphrase the source or bundled data of KiCad, LibrePCB, Horizon EDA, gEDA/Lepton or Fritzing. KiCad's symbol, footprint and 3D libraries are CC-BY-SA with an exception that covers designs, not redistribution in another tool's library: do not copy them either. Do not use KiCad MCP tools, plugins or files generated by these tools as references or fixtures.
- Commercial EDA tools (Altium, Eagle/Fusion Electronics, OrCAD/Allegro and similar) are proprietary: take no code, library data, text, icons, layouts or identifiers from them or their installations.
- Behavior comes from Pcbcraft's own documents, general electronics conventions, datasheets and public standards (for example IPC land-pattern and IEEE/IEC symbol conventions as published). Public file-format documentation may be used to implement future interoperability; implement from the specification, not from another tool's reader or writer.
- Permissive (MIT, Apache-2.0, BSD and similar) code may be adapted only with a row in [ATTRIBUTION.md](../../ATTRIBUTION.md) and its notice preserved. Solidcraft is MIT OR Apache-2.0 and may be consulted for conventions.
- Fixtures, example parts and test libraries are original synthetic data. Imported third-party library data records its provenance and license separately from code.

`cargo xtask licences --check` (part of `cargo xtask ci`) reads the locked dependency graph. It fails when a workspace crate does not declare `MIT OR Apache-2.0`, when a dependency cannot be used without a GPL, LGPL or AGPL license (`X OR GPL-…` passes only through a reviewed permissive `X`), and when a license id is unreviewed or missing. Add a license id to its reviewed list only after reading the terms. Unlabelled packages need a version-specific exception with a reason; exceptions never waive GPL-family terms and stale entries fail.
