# Design rules, net classes, copper fills and board shape (as built)

Four founder requests are built here: configurable manufacturing parameters with profiles for different production specifications, net classes, full copper fills, and board cutouts with a flexible, sketch-based board shape on which components are placed relative to any board edge. The work started from a contract slice (types and minimal bodies) and eight parallel tasks; this note records what was built. `crates/editor-core/src/tests/board_contract.rs` still pins the invariants below.

## Invariants

- **Rules come only from a fab profile.** Sparksmith ships no estimated values (founder decision, 11 November 2026); its only built-in profiles are the two sourced JLCPCB files (founder decision, 13 November 2026, below). A board's rules are the profile it pins plus its overrides; a board without a profile has no rules ([fab profile files](#fab-profile-files)); a fab profile is the file that holds them, the rules themselves are design rules (founder decision, 11 November 2026). The test prototype fixture (`rules/fixtures/prototype.json`, test builds only) holds the former hard-coded limits so the tests that measure against them still do: 0.2 mm copper clearance, 0.3 mm copper to board edge, 0.25 mm drill-to-copper and hole-to-hole, 0.1 mm annular ring and min drill, 0.05 mm mask expansion, 0.1 mm mask web and silk width, 0.6 mm silk text height, 0.3/0.6 mm tented vias, a 0.3 mm route width and the land-estimator margins. `the_prototype_fixture_holds_the_former_hardcoded_limits` pins this. `DesignRules::default()` holds the same values as a test fixture only (`test-fixtures`); the product's land estimators take the board's profile (`ProjectRules::land_estimators` refuses without one).
- **One typed engine.** New operations: `rules.set_fab_profile`, `rules.set_override`, `rules.clear_override`, `net_class.add`/`edit`/`delete`/`assign`/`set_patterns`/`set_clearance`, `fill.add`/`edit`/`delete`/`refill`/`store`/`store_all`, `keepout.add`/`edit`/`delete`, `board.set_rectangle`, `board.start_sketch`, `board.edit`, and (since the board sketch references design, docs/board-sketch-references.md) `layout.dimension_add`/`edit`/`delete`. New queries: `rules.effective`, `rules.fab_profiles`, `rules.preview_fab_profile`, `net_class.list`, `net_class.preview_patterns`, `board.shape` and `fill.status`. All of them come from `sparksmith_core::schemas()`, so the CLI and MCP reach them through the generic `apply` and `query`. Each command is one undo step, and a failed command leaves the document unchanged. A rules command that changes nothing is not an undo step.
- **Pre-release format.** The new `Project` fields (`rules`, `board_shape`, `part_dimensions`, `fills`, `keepouts`) are serde-defaulted and skipped when empty or default. There are no migrations.
- **Pure core.** Sketch solving runs behind host traits: `FootprintEvaluator` for footprints and `BoardShapeEvaluator` for the board. Hosts pass them as `Engine::apply_hosted(rev, op, Evaluators { footprint, board })`. The desktop app (`pcb_editor::board_shape::host_evaluator`) and the automation session both pass `sparksmith_solidcraft::board::SketchBoardEvaluator`. The user profile library lives in `sparksmith-io`.
- **Clean room.** Profile values come from fabricators' public capability pages, cited per rule with the page's URL and the date read. The shipped profiles are files in the shipped library (`library/profiles/`, [shipped library](shipped-library.md)), read at run time; no fabricator data is compiled in.

## Design rules and profiles

- **Core** (`rules.rs`, `rules/profile.rs`, `rules/formula.rs`): `ProjectRules` holds a snapshot of the chosen profile (none until one is chosen), per-project overrides, net classes, class assignments and patterns, and class-to-class clearances.
  - Values resolve in this order: profile, then override, then net class, then class pair. A `Region` source is reserved and has an explicit precedence.
  - `RuleSource::describe()` names the source in messages, for example "Fine 4/4" or "net class Power".
  - `rules::apply` is atomic. It names the rule in every bounds refusal.
  - `rules.set_fab_profile` takes any valid, sourced profile and refuses kept overrides that break it (`rules.override_conflict`).
  - `rules.preview_fab_profile` lists the rule changes, the dropped overrides and the board issues that would appear or go, matched by finding identity. A switch that would be refused is still previewed and carries its `refusal`.
  - `rules.set_fab_options {"options": {"limits": "minimum"}}` chooses [manufacturing options](#manufacturing-options) of the board's profile (options not named keep their choice) and keeps the overrides; `rules.preview_fab_options` previews it as a switch is previewed. `rules.effective` lists the profile's options and the board's choices (`profile.options`, `profile.chosen`).
- **Checks** read the effective rules. Two pads of one placed footprint are held to the profile's pad-to-pad clearance only, not to net-class or class-pair clearances: the footprint fixes their spacing (a QFN's pins cannot meet a power class's clearance to its exposed pad). The checks read: copper clearance, board edge with cutouts and slots (`layout/board_edge.rs` on `Project::board()`), via drill size, annular ring, aspect ratio, drill to copper, hole to hole, mounting holes, courtyard clearance, the footprint mask-web and silkscreen lint, and the land estimators. The routing and via refusals do too.
  - Messages give the rule, its value and its source after "; ", for example "…; needs 0.25 mm (Fine 4/4: min mask web)". The issue title is the first clause, so it stays the same when the profile changes.
  - `layout/limits.rs` caches the resolved limits for one check run.
- **Desktop.** The Board card's Rules row opens the docked Design rules panel (`pcb_editor/rules_panel.rs`).
  - The panel has a profile picker with the profile's source and a grouped rule table (profile value, a formula marked ƒ with the formula and the value's source on hover, effective value, Reset) with live overrides. A board without a profile says so and offers the library's profiles to choose.
  - A profile switch is previewed first. A refused switch shows its reason as a blocker. The switch commits as one `rules.set_fab_profile`.
  - The profile's manufacturing options are choice rows under its source. Choosing another choice opens the same review ("Change fab profile option": the rules that change and the issues that appear or go, with the option's source); Use these limits commits one `rules.set_fab_options`. Other choices of a library profile are not "Differs from the library version".
  - The panel also offers Save as profile and the user library: rename, delete, import and export.
  - Issues rows whose limit is a rule offer "Show rule".
- **Fab profile library** (`crates/io/src/rule_profiles.rs`): one `ProfileFile` (`PROFILE_FILE_FORMAT` 1) per profile, stored in `UserDirs::config/fab-profiles/`. Writes are atomic; reads are bounded (256 KiB per file, at most 256 profiles). Damaged or unsupported files are reported, never rewritten. The CLI has `fab-profile list|import|export`.

## Fab profile files

A fab profile is a versioned JSON file (`{"format": 1, "fab_profile": {…}}`, `deny_unknown_fields`); a project embeds the same profile object (`rules.profile`) as its snapshot, as library revisions are pinned, so a board reopens with exactly the rules it was checked against.

- **Source.** `source` names the `publisher` and the `date` (YYYY-MM-DD) the numbers were read, both required, with an optional `document`, `url` and `notes`. Each rule may carry its own `source` (the capability page's row); one without falls back to the profile's.
- **Every rule.** `rules` sets every rule by name (`RuleKey::name`: `drill_min`, `clearance_track_board_edge`, …) as `{"value": …}` or `{"formula": "…"}`. A missing, unknown or duplicated rule is refused, never filled in. A limit the fabricator does not publish is 0 (not checked) with a source saying so; a default that is the profile author's choice says that.
- **Formulas.** A formula is a Rhai expression of other rules (`via_drill_default + 0.15`, `silk_line_width_min / silk_text_height_min`). It runs sandboxed: an expression only, no loops, functions of its own, printing, `eval`, modules or I/O, and at most 10,000 operations. Formulas evaluate in dependency order after the values and after the project's overrides, so a formula follows an override of a rule it names; an override of the formula's own rule replaces it. A formula that names itself through any chain is refused with the chain (`rules.formula_cycle: … via_drill_default → via_diameter_default → via_drill_default`); one that names no rule, fails or gives a value of another kind is refused naming the rule.
- **Manufacturing options.** A fabricator's limits can depend on what is ordered (founder decision, 14 November 2026: "the limit depends on JLCPCB's profile; they have different limits depending on the selected manufacturing"). A profile lists `options`, each `{"id", "name", "default", "choices": [{"id", "name"}], "source"}`, and a rule lists `cases`, each `{"when": {"option": "choice"}, "value": …, "source": "…"}`: the first case whose every option takes its choice gives the value and its source, else the rule's own value applies. A case gives a value of the rule's kind and names only options and choices the profile offers; a profile offers at most 16 options of at most 16 choices, and a rule at most 16 cases. The profile keeps the choice of every option (`chosen`, each option's `default` until one is chosen), so a board pins its profile and its choices, and its rules are those of the choices. The rule's own value is the default choice's, so a profile reads the same without its options. The defaults are data in the profile file, the same for every way a board takes a profile (a new project, a switch, `project.new`, an import).
- **Drill files.** `drill_files` says how the fabricator reads drill files: `finished`, `drilled` with a `pth_allowance` (plated tools written at finished size plus the allowance, as Eurocircuits documents with 0.10 mm) or `not_published`. Hole sizes in Sparksmith are always finished sizes; the Excellon tool table, its comment line, the drill table and the fabrication drawing follow the setting.
- **One resolver.** `ProjectRules::effective` is the one resolution every check, tool default and output reads. A project without a profile resolves to `DesignRules::unset()` (every limit 0, no defaults); `ProjectRules::require` refuses tools and outputs that need one (`rules.no_fab_profile`): fills, sketched board outlines, the showcase. The production check blocks with an unwaivable `rules.no_fab_profile`.
- **New boards.** MCP and the stdio session's `project.new` never ask: they take `profile` (a library or built-in id, or a whole profile) and fall back to the user's default (`UserSettings::default_rule_profile`, set in Settings › Rules), else the shipped default that `library/defaults/new-project.json` names. That file also names the new board's size and its stackup family and layer count (`library/stackups/`, loaded by `sparksmith_io::new_project`): the core holds none of these values. The desktop's File › New and a launch without a file start on the default profile; without one, the PCB asks once (a "Fab profile" dialog, docked in the Design rules panel) with the shipped default preselected, and Use profile sets it as one `rules.set_fab_profile`. Cancel leaves the board without rules until one is chosen in Board › Rules.
- **Shipped profiles.** `library/profiles/jlcpcb-2-layer-1oz.json` and `jlcpcb-4-layer-1oz.json` are written from JLCPCB's [PCB capabilities page](https://jlcpcb.com/capabilities/pcb-capabilities), read 2026-11-11 and again 2026-11-14 (no value had changed), each rule citing its row. Both offer three options. *JLCPCB values* (default Recommended; Absolute minimum) holds the two rows that give both: "PTH annular ring" (2 layers: 0.25 mm recommended, 0.18 mm minimum; 4 layers: 0.20 and 0.15 mm) and "PTH to Track" (0.35 mm recommended, 0.28 mm minimum; on 4 layers the minimum is the inner-layer row's 0.3 mm, since one rule covers every layer). It is not an order option but which of JLCPCB's two values a board is held to. *Solder mask colour* (default green, red, yellow, blue or purple: 0.10 mm bridge; black or white: 0.13 mm). *Smallest drill* (default 0.15 mm; 0.1 mm for boards 1 mm or thinner with an ENIG or OSP finish, which costs more). The defaults give the values the files had before they offered options, so a board that switches to them again gets the same limits. Copper weight is not an option: the files are 1 oz (their ids say so), and 2 oz changes the track and space (0.16 mm on 2 layers, 0.15 mm multilayer), the PTH ring (0.254 mm) and the mask bridge (0.20 mm, any colour) as well as the stackup. JLCPCB does not say there whether drill files are read as finished or drilled sizes, so both say `not_published`. Both ship (founder decision, 13 November 2026; `sparksmith_io::rule_profiles::shipped_profiles`, read through `ShippedLibrary`; a missing or broken file is an error naming it): the Rules picker, Settings' default, `rules.fab_profiles` and `sparksmith fab-profile list` (`"kind": "built-in"`) list them after the user's profiles, and `get`, exports and `project.new` read them by id. They are read-only: Save as fab profile… makes an editable copy. A user profile with a built-in's id (an import of the same file, say) takes its place everywhere; deleting it brings the built-in back. Import other fabricators' files with `sparksmith fab-profile import FILE.json` or the panel's Import…, citing their pages.
- **Rules the profiles hold now.** The legend text stroke is `silk_text_stroke_share` of the text height and never under `silk_line_width_min` (it was a fixed 1/7 with a 0.1 mm floor). The via, route and pair tools start tented as `tent_vias` says. A via's drill is held to `drill_min`, not a fixed 0.1 mm floor (6 mm stays the document's pad bound). The coupled-gap tolerance is the pair class's `pair_gap_tolerance`, else the profile's `pair_gap_tolerance_share` of the gap and at least its `pair_gap_tolerance` (the former fixed 10 % and 0.02 mm, now the profile author's choice); the tightest pair gap is the track clearance (the 0.05 mm floor is gone); the "too close" band of three pair gaps is a cited constant (`layout::length::TOO_CLOSE_GAPS`).
- **Three hole kinds.** The clearance matrix pairs eight objects (36 rules): track, pad, via, fill, board edge, `via_hole`, `pth_hole` and `npth_hole`. A via's drill is `via_hole`; a plated pad or mounting hole (pad vias included) is `pth_hole`; an unplated pad or mounting hole is `npth_hole`. The via, mounting-hole and pad-hole checks and fills each read their hole's kind. The JLCPCB examples hold copper to a plated hole at the recommended 0.35 mm ("PTH to Track": "0.35mm is recommended, minimum 0.28mm"; on 4 layers this is also above "Inner layer PTH pad hole to copper clearance": 0.3mm), copper to an unplated hole at "NPTH to Track" 0.2 mm, and plated hole spacing at "Pad Hole-to-Hole Spacing" 0.45 mm. JLCPCB publishes no unplated hole-to-hole, unplated-to-via or unplated-to-plated row; by founder decision (12 November 2026) the examples read "Pad Hole-to-Hole Spacing" 0.45 mm as covering unplated pad holes too, and each of those rules says it is that reading. It publishes no hole-to-edge row, so those pairs are 0, not checked. The NPTH pad annular ring (`npth_annular_ring_min`) is "NPTH pad annular ring": "≧0.45mm". `cargo xtask convert-v1` gives a profile without `npth_hole` rules its via-hole values, noted in each rule's source, and an unchecked (0) NPTH pad annular ring, and copies each override of a `via_hole` pair to its `npth_hole` twin.
- **Pad hole checks** (`layout/pad_hole.rs`). `board.pth_annular_ring`: every plated pad hole (slots and pad vias included) leaves at least `pth_annular_ring_min` of copper to its pad's outline (one outline on every layer the pad has copper on), and every plated mounting hole as much to its ring; a round hole is measured exactly, a slot at its outline's vertices (exact on convex lands). `board.pad_hole_clearance`: a pad hole passes through every layer, so every track, pad and via within its kind's clearance is reported, except copper the copper graph joins to the hole's own pad; same-net copper that does not reach the pad is measured. `board.pad_hole_spacing`: a pad hole against every other pad hole, via drill and mounting hole by the hole-kind pair, whatever the nets. Fresh fills keep these clearances by construction; a hole through stale fill copper is a `fill.clearance` overlap. `board.npth_annular_ring`: an unplated hole in a pad with copper leaves at least `npth_annular_ring_min` of copper (a bare unplated hole has none and is not measured). Via rings keep `board.via_annular_ring` (`layout/via.rs`). A waived production finding is printed in the fabrication drawing notes with its reason, asking the fabricator to confirm it in DFM review. The ESP32 example waives its two J1 locating-peg findings (0.175 and 0.177 mm to the A1B12 and B1A12 GND lands, under 0.2 mm), which follow the GCT USB4105 drawing rev B4.
- **Fabrication outputs.** The fabrication drawing states the nominal thickness over the outer copper with solder mask and legend excluded, and lists the mask rows at the stackup's mask thickness; the job file gives each solder mask its thickness.
- **Converting files.** `cargo xtask convert-v1 [--profile PROFILE.json] FILE.sparksmith|OLD_PROFILE.json…` rewrites an old snapshot: into the given profile, keeping overrides, or (for a profile the user entered from a fabricator, with a source and date) into the new form with every rule named. An estimated built-in snapshot without `--profile` is refused, naming it. Old profile library files convert in place.
- **Land estimates.** The land estimators (`library::samples`, `package_form::tht`, the footprint templates) read the board's profile (`tht_drill_clearance`, `tht_land_extra`, `tht_land_gap`, `gull_wing_toe_shift`, …); a board without a profile refuses to estimate lands. Still to do: the no-lead land gap from the mask-expansion constant (W4) and the inline header and no-lead land margins (N4).
- **Impedance tolerance.** A net class's impedance target sets routed widths; routed impedance is checked only against a tolerance the class states (`impedance_tolerance`): there is no default tolerance.

## Net classes

- **Core** (`rules/netclass.rs`):
  - Each class has a track width, a minimum width, a clearance, a fill clearance, a via drill and diameter, and a fill connection. Its pair width and gap, impedance targets and pair limits are in [high-speed routing](high-speed-routing.md).
  - A class's fill clearance replaces its clearance in any pair with a fill, whichever side the class is on; unset, the clearance applies to fills too. It can be lower or higher than the clearance. The rule's fill clearances and class-to-class clearances still set the floor, and tracks and pads never read it (`fill_clearance_applies_to_fills_only`, `a_fill_clearance_leaves_a_tight_route_routable`).
  - A class's values are checked against each other.
  - An explicit assignment beats the first matching name pattern (`*`/`?`). Nothing else assigns a class.
  - Assignments follow nets through `nets::reconcile`:
    - A survivor without its own class inherits the merged-away nets' class when they agree.
    - A net that splits off takes its origin's class.
    - Nets that are gone drop their assignment.
  - `net_class.list` reports every class with its resolved values and every net with its class and basis.
- **Routing.** `layout.route`, `route_apply`, `track_set` and `route_layer_change` refuse widths below the net's class minimum or the rule minimum. `layout::route_width` and `layout::class_via` give the class defaults. Clearance checks use the class and class-pair values, and so does a library update's impact preview (`layout::track_pad_clearance_conflict` and `via_pad_clearance_conflict` take `limits::BoardRules`; `the_impact_plan_reads_net_class_clearances`).
- **Desktop.**
  - The Route tool starts at the routed net's class width; a typed width stays for that net. The Via tool and layer changes place the class's via. While routing, W and D step through the presets of the rules: the net's own values, the defaults and every class's values, never below the minimums (`layout::route_widths`, `layout::via_sizes`, `layout::via_size_fits`).
  - The Track, Via and schematic Net cards have a Class row.
  - The Net classes card (`pcb_editor/net_classes.rs`) shows classes, values, class-to-class clearances, members and name patterns. It opens from the Board card's Net classes row; it and the Design rules panel replace each other in the subject slot.

## Copper fills and keepouts

- **Region.** A fill's `region` is stored, never inferred from its coordinates. `drawn` (the default) keeps its own outline at fixed board coordinates. `board` follows the board: after every operation `layout::fill::follow_board` gives it the solved board outline, so a board parameter or shape edit (`width`, `height`, `corner_r`, a sketch edit) moves its region at once, and its copper is stale until the next refill (the desktop's background refill, or `fill.refill`). A `fill.add` with `region: board` needs no outline. Editing a board-following fill's outline is refused (`fill.follows_board`) until it is made a drawn fill, which keeps the outline it has; a part dimension on one is refused too. The Fill card's Region row switches between Board outline and Drawn, and a board-following fill has no outline handles (`a_board_following_fill_grows_with_the_board_width`).
- **Computation** (`layout/fill.rs`, `layout/fill/compute.rs`) is a pure, deterministic function of the project. It uses `i_overlay` (MIT OR Apache-2.0; see [attribution](../ATTRIBUTION.md)). For one fill:
  1. The fill's outline is clipped to the board outline, shrunk by the fill-to-board-edge clearance.
  2. These are subtracted at the effective rule and net-class clearances: cutouts and slots, mounting holes, keepouts, other-net copper and higher-priority fills.
  3. Same-net pads and vias connect solid or through thermal reliefs (spoke count, width, gap and angle). The style is set per fill for surface pads, through-hole pads and vias (`settings.connections`), then by net class, then by rule.
  4. A minimum-width opening drops slivers.
  5. Hatching and island removal are options. An island is joined when copper of the fill's net on its layer touches it, by the copper graph's one joining rule ([copper graph](copper-graph.md)).
- **Results.** The copper (`FilledCopper`: its islands and the count removed) is stored on the fill with the key of its inputs. What the islands join is not stored.
  - `inputs_key` covers only the objects within the fill's reach, so an edit elsewhere leaves the fill fresh.
  - `fill.store` refuses copper whose key is stale; `fill.store_all` stores several fills as one undo step and refuses the whole batch when any key is stale.
  - The copper graph joins a fresh fill's islands to the pads, vias and tracks they touch, for board connectivity and airwires. Stale copper joins nothing, so an airwire shows as soon as a joined pad or via moves off the pour.
  - Fill copper is bounded per fill (2^20 vertices) and per project (2^23).
- **Checks:** `fill.clearance` (other-net copper overlapping stale copper; a stale fill otherwise carries only its one `fill.stale`, so a profile switch does not list every gap the refill will fix), `fill.empty`, `fill.island_unconnected` (an island of fresh copper that the copper graph joins to nothing, kept because the fill keeps every island), `fill.net_missing`, `fill.stale` and `keepout.track`/`via`/`pad`.
- **Background refill.** The desktop fill worker (`apps/sparksmith/src/fill_worker.rs`) computes stale fills off the UI thread with `FillCache` and `compute_stale`. It stores them with `Engine::store_fills`, which adds no undo step and computes the keys of the stored fills only.
  - An explicit refill (the Fill card's and Layout's Refill) also runs on the worker. The app commits its copper as one undoable `fill.store_all` and says "Refilling in the background" meanwhile; a refill whose revision moved on is computed again. The CLI and MCP keep the synchronous `fill.refill`.
- **Measured** (1 November 2026, macOS arm64, release build): one fill of a 200 × 200 mm plane over 10,000 through vias took 1.40 s, and its inputs key 2.1 ms (`a_large_board_fills_in_seconds`, which prints both).
- **PCB 2D** (`fill_paint.rs`, `fill_tool.rs`, `fill_card.rs`):
  - Fill copper is drawn under its layer's tracks: solid, hatched or outlines only, set in the view popover's Fills row. On the active layer it is the layer's opaque colour; on another layer it is lighter than that layer's tracks (a translucent tint with its outline), so a pour never hides the active layer ([PCB realism](pcb-realism.md#pcb-2d-appssparksmith)). It is triangulated once per copper with `spade` and cached.
  - Keepouts are drawn as hatched outlines over all copper, labelled with the layers they apply to, in every layer focus mode.
  - Unfilled fills show as dashed outlines.
  - The selected fill's outline has vertex and midpoint handles. Each release is one `fill.edit`.
  - The Fill tool draws outlines with lines and three-point arcs. The Fill card edits net, layer, priority and settings, with Refill and Delete in its footer.
- **PCB 3D** (`crates/solidcraft-integration/src/project/fill.rs`):
  - Each region of fill copper is a saved `FillCopper` body, one component per fill, on its layer and as thick as its foil. Its loops are simplified to 10 µm (`MODEL_CHORD_MM`, Douglas–Peucker) first; the document's 5 µm copper gives a pour thousands of faces. The regions go into one sketch command each (`Native::batched_body`), and the fill components are joined to the board with every other part at the end of the build.
  - An inner fill lies in its own foil level of the laminate (`fill::foil_level`), as inner tracks and via rings do in the stacked-slab laminate ([PCB realism](pcb-realism.md#saved-physical-bodies)): the fill's regions, united with every track, via ring and hole that overlaps them, are holes of that level's slab, so the saved bodies do not interfere and the laminate's mass is physical, with no Boolean. A round ring joins that union as a circumscribed 64-gon, so the laminate stays clear of its exact circle; copper that does not touch the fill keeps its exact circle. Laminate left in a clearance (round another net's via) is a body of its own, `Substrate 2 (2)`, … (`an_inner_fill_lies_in_its_own_foil_level`).
  - Outer fills get a display-only mask cap.
  - (Before stage A4, which removed the in-place update of the native board.) A fill edit updated the model in place (`fill_edits_update_the_filled_board_in_place`): the fill bodies' sketches, and an inner fill's foil slab, are redrawn. An extrusion whose profile pick named redrawn curves (a region with holes, a slab in pieces) is rebuilt from its command (`timeline.redefine`), which picks the redrawn profiles as a fresh build does. An edit that leaves a slab in other pieces (a drill moved through an inner fill splitting or joining laminate) still updates in place: the pieces as evaluated get the laminate's kind, look and saved identity, as in a fresh build.
  - Measured (2 November 2026, macOS arm64, `ci` profile, load average about 5): the shipped showcase exports (`sparksmith export`) in 2.3 s, against 8.3 s for this batch before the merge with the via-scaling work; the filled `Engine::showcase` builds in 1.16 s (`build_timings`; 0.85 s unfilled on the via-scaling branch). `the_showcase_fills_cost_little_of_the_build` keeps the filled showcase within 1.25× of the same board unfilled.
- **Showcase.** `Engine::showcase` has a bottom GND pour, an inner GND plane and ten stitching vias and refills them. The shipped file (`sparksmith showcase`, `Engine::showcase_hosted` with the sketch evaluators) adds a Power class over GND and VCC (0.5 mm tracks, 0.25 mm minimum, 0.4/0.8 mm vias, the profile's clearance), a top GND pour (thermals to the header and vias, solid to surface pads), and a sketched board: 2 mm rounded corners through `corner_r`, a 3.5 mm round cutout, a 1 mm milled slot and J1 held to the left edge at `height / 2 - 1 mm`. Its board checks are clean (`the_shipped_showcase_has_its_shape_classes_and_edge_held_header`).

## Etch hazards: acute copper angles and unfilled slivers

Two warnings of the board checks (`layout/etch.rs`, run by `layout::checks_with`, so by Issues and the production check). Both rules are in the design rules (`DesignRules::etch`, `EtchRules`), edited in the Rules panel (Copper › Min copper angle, Fills › Min sliver width) and through `rules.set_override` / `rules.clear_override` on `copper_angle_min` and `sliver_width_min`.

- **Defaults: unset (0, "Not checked").** We found no IPC figure or major fabricator's DFM number we could cite for either. A search (9 November 2026) turned up only vendor blog posts, which disagree with each other (some call any angle under 90° a risk, others accept 90°) and give no sliver width for bare gaps. So both ship unset: a min angle or width of 0 has nothing under it. Enter your fabricator's numbers to check them. Angles take 0–180°, widths 0–25 mm.
- **Check-only.** Fills do not read them: `ProjectRules::without_checks` leaves them out of the fill inputs key, so setting either leaves every fill fresh (`etch_rules_leave_fills_fresh`). Unset, they are left out of the saved rules.
- **`board.acute_copper`**: a bare wedge between joined copper edges on one layer narrower than the min copper angle. The copper graph finds them (`CopperGraph::wedges`, `layout/connectivity/wedges.rs`), from its joints only, on straight edges:
  - track to track where the centre lines meet (corner, T, crossing): the wedge between consecutive centre-line rays, at the apex where the facing sides cross. A wedge whose apex lies past a track's round end is not reported.
  - track to pad where a track side crosses a straight pad edge (rectangle sides, the straight parts of rounded rectangles and oblongs, a custom outline's line segments). Round pad edges and vias are not measured.
  - track to fill where a track side crosses an edge of a fresh fill island of its net, on the stored copper. The fill edge's direction is its chord over the track's half-width from the crossing: exact on a straight edge, and not one short chord's direction on a flattened curve. A notch shallower than that half-width is not reported.
  - A wedge that other copper of the net fills (a pad at the corner, a pour over both tracks) is no wedge. One finding per pair of objects, at its sharpest wedge.
- **`board.copper_sliver`**: inside a fresh fill, a bare gap narrower than the min sliver width between two pieces of copper of nets other than the fill's (tracks, vias, pads), or between such copper and the board edge, that the fill did not flow into. The gap is measured between the outlines the copper graph and the clearance check use, at its narrowest point; it is a sliver when that point is inside the fill's outline and the board, outside keepouts that forbid fills, and no copper (the fill's own, another fill's, any track, pad or via) crosses it. Two pads of one placed part are left out: the footprint sets their gap, as the clearance check treats them. At most 1,000 findings, then `board.check_limit`.
  - Fill slivers: fill compute already removes solid copper narrower than the fill's min width (an opening, `fill_slivers_are_removed_and_thin_hatches_are_reported`). A hatched fill whose hatch width is under its min fill width is reported as `board.copper_sliver` on the fill, whatever the sliver rule.
- Each finding names its objects (tracks, pad, fill, the board for an edge) and gives the location in its message, for example "Copper angle 30° < 90°: a track on VCC / a track on VCC on Top at (10.467, 10.125) mm (project override: min copper angle)" or "Unfilled gap 0.4 mm < 0.5 mm: a track on VCC / a track on GND in EN fill on Bottom at (20, 15.325) mm (…)".
- **Measured** (9 November 2026, macOS arm64, `test` profile: core at opt-level 1): on the 10,000-via benchmark board with a full-board pour and both rules set, the etch checks take 10.6 ms (angles 4.1 ms, slivers 6.9 ms, of which finding the fresh fills is 3.1 ms); unset, they cost nothing (`the_check_is_cheap_on_ten_thousand_vias` prints these).
- **The ESP32 example** keeps both unset, so its board and production checks have no etch finding (`crates/io/tests/esp32_etch.rs`). Under a 90° angle and its fills' flow limit (2 × 0.3 mm fill clearance + 0.2 mm min width = 0.8 mm) it has 25 acute wedges and 197 slivers; the test prints them.

## Board shape, cutouts and edge-relative placement

- **Model** (`model/board.rs`, `layout/outline.rs`):
  - `BoardShape` is a `Rectangle` (from `board_size`) or a `Sketch(BoardSketch)`. A sketched board keeps `board_size` at its solved bounding box.
  - `Project::board()` returns the solved shape: the outer outline, cutouts, slots, mounting holes and named edges. For a rectangle, the edges are bottom/right/top/left.
- **Sketch** (`crates/solidcraft-integration/src/board.rs`). `SketchBoardEvaluator` runs on the footprint sketch machinery: canonical sketch check, parameters in Solidcraft's expression language, bound dimensions and the solver.
  - `board.start_sketch` turns the rectangle into a fully constrained sketch driven by `width` and `height`.
  - `board.edit` applies sketch edits, parameters, outline/cutout/slot/mounting-hole roles, edge names, real tangent fillets and milled slots as one undo step. Its outcome (`board_edited`) lists the points, curves and constraints it created and kept, so a client can name them in the next edit. A fillet keeps a virtual corner, so dimensions and named edges still run corner to corner: `board.shape` reports a filleted board's `bottom` edge from (0, 0) to (w, 0) while its `outer` loop's line runs between the fillets. A part dimensioned to the edge measures to its line, so it stays put when the corner radius changes.
  - The edit is refused when the shape is unsolved, over-constrained, open or out of range.
- **Part dimensions** (`layout::dimensions`, design in [board sketch references](board-sketch-references.md) §5.2) replaced edge constraints. They are solved after every operation that touches them, on Solidcraft's sketch solver behind the board evaluator.
  - A placement, fill or keepout is held by dimensions and constraints between its origin, axes, pads, courtyard or anchors and board points and curves (or other parts). Values are numbers, board parameters or expressions over them. Parts move when board parameters change; a degree of freedom no dimension fixes keeps its value.
  - A move is a solver drag: a part dimensioned to one edge slides along it. A move that cannot land is refused with the reason and the way out: "J1 is held 2 mm from the right edge; edit or delete its dimensions to move it" (`dimensions::held_message`). A locked part's move is refused as "J2 is locked; unlock it to move it". `layout::move_refusal` gives a client either text before it tries.
  - A dimension whose part, pad, anchor or board geometry is gone stops driving and is reported as `board.reference_lost`, which blocks fabrication output with no waiver. A stored sketch that no longer solves is reported as `board.shape_unsolved`.
  - A dimension can also name a face, edge or vertex of a part's part file by its persistent Solidcraft name, body and a pick point in the model frame (slice S3, [board sketch references](board-sketch-references.md) §14). The host traces it in the board plane (a face square to the board is a line, a vertical hole or boss its centre); a sloped or flat face is refused. A reference the part file no longer has is `board.reference_lost`; one found but not provably the same is `board.reference_inexact`. Both block fabrication output, and a library update lists them first in its preview.
- **3D.** Every laminate slab is extruded from the solved outline with its cutouts, slots and mounting holes as holes (no Boolean); a sketched board's slabs do not follow `board_width` and `board_depth`. The display-only mask films follow the solved outline (inset 0.03 mm) and open over every cutout, slot and mounting hole; the edge bands line the outline and each cutout and slot (`the_mask_and_edge_bands_follow_the_sketched_shape`). Fill computation and board-edge checks read the same shape.
- **Desktop** (`board_shape.rs`, `board_shape_ui.rs`, `edge_card.rs`):
  - Layout's Shape button opens the Board shape mode on the footprint editor's sketch view.
  - The tools are Line (L), Arc (A), Circle (C), Rectangle (R, with a parametric corner radius), Spline (S), Ellipse (Shift+C), Conic (Shift+A), Fillet (F), Dimension (D, bound to board parameters), Cutout (U), Slot (Shift+H), Mounting hole (H) and Name edge (E). X toggles construction geometry. Every gesture is one `board.edit`.
  - The free-form tools follow Solidcraft's. Spline takes fit points (or control points); a click on the first point closes a fit-point spline smoothly, and Enter, a double-click on the last point, a right-click or the card's Finish ends it open; Backspace takes back a point and Esc drops it. Ellipse is the centre, the end of the major axis, then a point on it. Conic is the start, the end, then the apex, with the card's Rho (0.5 a parabola). Clicks on existing points are tied to them in the same step, so a conic or spline can close a loop with other curves. The preview is the curve drawn in a scratch sketch (`sparksmith_solidcraft::board::free_form_preview`); it never touches the document.
  - The Placement section opens with the part's state: "Free · nearest: right" with "Dimension to edge", which adds the part's distance to the nearest named edge in place; "Held 2 mm from the right edge" (with "Free part" when one dimension holds it); or "Locked in place". A dimensioned part's Dimensions section edits each value live and deletes any one, and the canvas draws its distances to named edges while it is selected. Dragging it previews where the engine lands it (`dimensions::landing`).
  - Unselected, a dimensioned part carries Solidcraft's Dimension glyph with a `dimension` rim and a locked part the Fix glyph with a `sketch_locked` rim, just outside the top-right corner of its envelope (`pcb_editor/hold_mark.rs`). Free parts carry nothing. The glyph keeps its screen size and becomes a dot of the same colour when the part is smaller on screen than the glyph.
  - The Board card shows the shape and edits the board parameters.

## Limits

- Push-and-shove was not part of this work; routing respects class widths and the rule minimums. It was built later on the seam described in [high-speed routing](high-speed-routing.md#the-push-and-shove-seam); see [push-and-shove](push-and-shove.md).
- Document validation still bounds vias by the board's bounding box (`board_size`). A via outside a sketched outline but inside its bounding box is a board-edge finding, not an invalid document.
- The Board shape mode, the Fill tool and card, the Net classes card and the Design rules panel are covered by engine and egui-frame tests (`the_host_evaluator_solves_a_cutout_gesture_on_the_engine` drives a Cutout gesture through the linked sketch engine).
- The shipped showcase's cutout and slot are drawn at coordinates, not dimensioned, so its sketch solves under-constrained; its outline is fully driven by `width`, `height` and `corner_r`.
- `rules.preview_fab_profile` runs two issue reports on the UI thread; it has not been measured at 10,000 vias.
