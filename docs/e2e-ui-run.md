# End-to-end run through the desktop UI: USB sensor board, 30 minutes

On 5 November 2026 an agent tried to design a small USB-powered sensor board in Pcbcraft's desktop app, the way a person would: through the ribbon, the cards, the canvas and the shortcuts. The app ran in the Herdr macOS VM (macOS 27.2, 1380 × 900 window). The build was 986e8ac with the `ci` profile. The founder set a budget of **30 minutes of design time**, counted from the first action in the app (build and deploy excluded), and watched the VM during the run. The design started at 14:40:15 and ended at 15:08:03. The agent read no product source to find its way. It changed no product code. No step fell back to `pcbcraft-cli`.

The goal is a short, honest answer to the question "how far does a board get in 30 minutes, and where does the time go?". The command-level gaps are in [the ESP32 run](e2e-esp32-devboard.md); they are not repeated here.

## Outcome

**The board reached step 6 of 12 (placement), unfinished.** It has 13 parts and a parametric outline with four mounting holes. One part is constrained to an edge and one is locked. The schematic is wired in part, there is one stub of track, and there is no pour and no output.

Where the time went: **parts took 39% and the schematic 36%**. That left about 7 minutes for the board, which was not enough for routing, the pour, checks or output. Inside the parts step, setting each imported pin function's kind by hand took about 5 of the 11 minutes (finding 2).

No example was committed under `examples/`. The board is incomplete, and its land patterns are the templates' "estimated template defaults", not datasheet or vendor land patterns, so it does not meet the provenance bar. The screenshots stayed in the agent's `target/e2e/` and were not committed.

### Finding 3, fixed

- **⌘Q quit without asking.** winit's default macOS menu has a Quit item with ⌘Q that sends AppKit's `terminate:`, which ends the app at once. No close request reaches the app, so the existing unsaved-changes prompt (on the window's close button) never ran. The app menu is now Pcbcraft's own (`apps/pcbcraft/src/native_menu.rs`, muda, as in Solidcraft). Its Quit runs the new registry command `app.quit` (⌘Q, rebindable), which makes the same request as the close button. egui's built-in ⌘Q, which closed the window directly, is off.
- **Every quit path now:** ⌘Q, the app menu's Quit and the window's close button ask *Save changes before quitting?* with **Save**, **Don't Save** and **Cancel** in the app's dialog style. Cancel changes nothing, and the recovery snapshot stays. Save writes the file (it opens the save panel first for an untitled project; cancelling the panel asks again) and then quits. Don't Save quits and removes this session's recovery snapshot, as in Solidcraft. A quit during a save or an open file panel waits for it and then asks. A quit while the startup recovery question is open leaves those snapshots for the next launch. A quit with nothing unsaved closes at once. The prompt is drawn inside the frame, so a test or automation that requests a close never blocks.
- **Dock › Quit** (and a logout) still ends the app without asking. AppKit asks the application delegate, which is winit's and has no `applicationShouldTerminate:`. Adding one needs `unsafe` Objective-C runtime code, which Pcbcraft forbids, or a change to Solidcraft's vendored winit. Instead, the exit now writes the latest edit to the recovery snapshot (waiting up to 5 s), so the next launch offers it.
- **One document per window.** Pcbcraft has one window and one project, and the component drafts are part of that project, so one answer covers every workspace.
- **Recovery snapshots** are written 2 s after the document stops changing, whenever it has unsaved changes not yet in a snapshot. A failed write is retried after 10 s. A crash therefore loses only the edits made since the document last rested for 2 s. The interval was not changed.
- **⌘S** is `file.save` in every context, including the board shape sketch's exclusive mode. It runs while a field is focused or a menu is open, and the board shape card and canvas leave it for the dispatcher (`command_s_saves_everywhere`, `the_shape_mode_leaves_command_s_for_the_dispatcher`). No code path that drops ⌘S was found, and winit's menu had no ⌘S key equivalent to take it. The failure is therefore most likely the driver's key delivery, as the run suspected, but that is **unconfirmed**: it needs a check by hand in the VM.

### Founder's parametric checks

- **Parametric holes: worked well.**
  - With the Dimension tool, click a hole and then an edge, and type `inset = 4` in Value. That creates a board parameter and drives the dimension. The other seven dimensions took `inset` by name, and the sketch reported "Fully defined" (`finding-holes-free.png` shows before, `finding-inset-6.png` shows after).
  - Changing `inset` to 6 in Board parameters moved all four holes at once. ⌘Z restored 4.
  - Changing the width from 60 to 56 moved only the right-hand holes, and J1 (constrained to the right edge) followed. The bottom-left dimension labels sit on top of each other (polish).
  - Not checked: the pour and DRC following the change, because no pour had been made by then.
  - About 2 minutes and roughly 25 clicks for four holes. A hole tool option such as "inset from corners" would make it one step.
- **Fixed parts:** see findings 8–10. The constrained part's dimensions show only while it is selected. The locked part's card is clear. On the canvas the two states can't be told apart, and the refusals don't say why.

## What worked well

- **The Place palette.** P, type, Enter, click placed 13 symbols in about a minute.
- **New from template** for passives, SOIC parts and headers. Each one was search, pick, Create, Publish in about 20 s, with symbol, footprint and 3D body together.
- **Paste table preview** showed the parsed rows and column roles before applying, and named the problems.
- **Update PCB** as a reviewed, undoable step. ⇧⌘U and the ribbon both reached it.
- **The parametric board sketch:** named parameters in dimensions, "Fully defined" feedback, and edits that propagate with clean undo.
- **The 3D view** opened in about 5 s and showed headers, SOIC bodies, passives and holes (`finding-3d.png`).
- **Recovery** brought back everything that ⌘Q without a prompt would otherwise have lost.
- **The Issues card** stayed visible throughout, with counts that tracked every edit.

## Driver limits, not product problems

- Native Open and Save panels: the file name typed into the save panel did not arrive.
- Possibly tab characters in typed text (finding 17), and possibly ⌘S (finding 3, unconfirmed).
- Each driver action takes about 1–2 s, so 30 minutes through the driver is worth fewer clicks than 30 minutes by hand. The proportions (parts and schematic about 75%) are the main result, not the absolute stage reached.
