# Parts library

Design, decisions and slice plan, 30 October 2026. Condensed from the reviewed design proposal. **Slice S1 is implemented** (see [S1 as built](#s1-as-built)). S2–S5 are plans. Every estimate and performance figure is labelled a target, an estimate or a measurement. Nothing here is legal advice.

## Summary

Pcbcraft already has immutable revisions, exact references, drafts, publish cascades and reviewed updates ([component model](component-model.md), [part library design](part-library-design.md)). The parts library adds a **catalog layer** around that core:

- **Sources:** the project snapshot, later also local library folders shared as plain files or git.
- **A manufacturer-part record** (`Part`) next to the generic component.
- **Labels for finding things** that never act as identity: shelves, tags and data-derived facets.
- **One unit-aware search function in the core.** The Place palette, the Browser, the CLI and MCP all call it.

Placing from a library copies the full dependency closure into the project in the same undoable transaction. The project never resolves anything through a folder or index, so it still reopens offline.

## Data tiers

| Tier | What it is | Authority | Where it lives |
| --- | --- | --- | --- |
| Project snapshot | Every revision the project references, with its closure and asset bytes | Authoritative for the design | `Project.library` |
| Library sources (S3) | Local folders of immutable revisions, read-only or writable | Authoritative for new imports only | On disk, listed in per-user settings (io) |
| External catalogs (S5) | Optional supplier connectors returning observations | Never authoritative; expires; never shared | Per-user cache only |

## Library items

A Library row is a **lineage**: one identity with many immutable revisions.

- **Component lineage** (exists): the generic electrical interface with its symbols and bindings.
- **Package and footprint variants** (exist).
- **`Part`** (S2): a revisioned lineage holding the manufacturer, the complete MPN, a pinned `ComponentRef` and `BindingRef`, rated specs as typed field values with a comparison meaning, references and provenance. The publish cascade grows to footprint → binding → component → Part. An instance's `PartRef` must agree with its own component and physical choice; a component update that leaves a Part pinned to the old revision raises a finding and an update choice and is never re-pointed silently. An "atomic part" in other tools is a component plus exactly one Part.
- **Reference** (S2): datasheet or application note link with stable local ID, kind, title, URL, optional document revision, optional asset hash, licence and provenance. A link is not a copy.
- **Distributor offer** (S2): distributor name, SKU, product URL, optional packaging. No price or stock.
- **Lifecycle observation** (S4): normalised status, the source's raw label, source, observed-on date and optional last-buy date. Authored or imported by the user; it never changes existing designs.

**Generic first, exact later.** An instance keeps its typed requirements and may also pin an optional `PartRef` (on `model::ComponentInstance`; rules in `instances`). One pure predicate, `fields::satisfies(requirement, spec)`, compares them by declared meaning (exact nominal, minimum rating, maximum tolerance) and is shared by search, `instance.assign_part` and purchasing completeness.

**Organisation without identity.** A *shelf* is an optional shallow path label; *tags* are free-form user labels; *facets* are derived from the fields the results carry. No category is hard-coded, and no vendor, EDA, IEC CDD or ECLASS taxonomy is copied. Shelves and tags live with the source that owns the lineage, outside revision identity (D13).

**Health** (S4) is derived like completeness, never stored: missing footprint, binding or model; unmapped terminals; no Part; unknown provenance or licence; no review record; risky lifecycle ("today" is an input); duplicate MPNs; a newer revision in the source. It is a filter and a report, never a gate.

**Provenance** (S2) becomes structured: `origin` (library, source lineage, revision, content hash), `basis` (authored, from a reference, imported), licence and the existing free-text note.

## Query language

`parse_query(text, &Vocabulary) -> Result<CatalogQuery, QueryError>`. Input is at most 512 bytes and 16 terms. Terms are ANDed.

- **Free text** matches names, descriptions, package labels and field texts, case-folded. `"…"` keeps spaces and is always text.
- **Reserved filters:** `pkg:` (a text match on package names only; it implies nothing about compatibility), `has:` and `missing:` (`symbol`, `footprint`, `3d`, `mpn`), `src:project` and `kind:component` (the only entry kind in S1, so it keeps every entry). `tag:`, `shelf:`, `mpn:` and `life:` are reserved and report that their data does not exist yet. Reserved keys are checked first, so a field named `Kind` or `Life` is reached through a shorter prefix of its name (`kin:`, `lif:`); an unknown-key message lists the fields and the reserved filters.
- **Field predicates:** `key op value` with `>= <= > < = :` and ranges `key:min..max`. Keys are data, resolved in an order that never depends on which other fields exist: a key that spells a unit symbol or alias of any field's quantity kind (`V`, `kV`, `Ω`, `ohm`, `R` where the data declares it) is always a **unit key** and names every field measured in that unit; any other key is a field name, exact or a unique prefix (`res`, `tol`, `volt`). The code holds no field names, units or category branches. An ambiguous prefix or an unknown key is an error that lists the fields.
- **Values** are read by `quantity::parse` against the field's own unit set, after an **RKM pre-pass**: a letter used as the decimal point becomes a decimal (`4k7` → `4.7k`, `2u2`, `4R7`, `R47`). Multiplier letters are the one-letter SI prefixes; unit letters are the one-letter symbols and aliases of the field's unit set, so `R` is a decimal point only where the data declares `R` (as the synthetic resistance kind does).
- **Dimension check:** a unit key filters every field measured in that unit, so its value is a plain number in the key's unit (`V>=25`) or states a unit of the same kind (`V>=0.025kV`). A bare multiplier after a unit key is always refused instead of being guessed: `V>=10k: 10 k has no unit of voltage`, and, where the data declares `R` as an alias of Ω, `R>=10k: 10 k has no unit of resistance` (write `R>=10kΩ` or `res>=10k`). After a field-name key a bare multiplier reads in the default unit, as in property entry (`res>=10k`, `volt>=10k`). Adding or renaming a field never changes what a unit key means.
- **Meaning:** comparisons "meet", not "equal". `tol<=1%` matches ±0.5 % and ±1 % (each side compared). A range field reaches a bound (`≥` its maximum, `≤` its minimum) and covers a `min..max` predicate. Quantity equality allows a relative 1e-9.
- **Bare values** with a letter (`10k`, `4k7`, `100nF`) are tried against every quantity field they read as, and as text; the chip shows each reading. Plain numbers such as `0603` stay text.

## Ranking

1. **Match tier**, worst over the text terms: exact name or lineage ID, name prefix, whole word, substring (name, description, package), field value only. A query of filters only ranks every match equally.
2. **Boosts:** used in this project, favourite, recently used (most recent first). Favourites and recents are inputs (`CatalogContext`); the core reads no settings.
3. **Final ties:** folded name, source, lineage ID.

Equal inputs always give the same order, whatever the entry order. Hidden entries are counted by reason ("1 hidden (unpublished draft)"), never dropped silently. Stock or price never reorders results.

## S1 as built

**Core (`pcbcraft-core::catalog`, module-map row 14).** Pure and wasm-compatible; it may use `ids`, `diagnostics`, `quantity`, `fields`, `library` and `model` (narrowed to what S1 imports; later slices widen the row when they need `instances` or `completeness`). `updates` (0–16) and `commands` (0–17) widened to include it.

- `entries(&Project, &Drafts)`: one `CatalogEntry` per component lineage at its latest published revision, then lineages that exist only as drafts (`revision: None`, not placeable). An entry holds the source (`project`), name, description, the effective default of each selected field (component default, else field default) formatted in core, package names as labels, separate badges (symbol, footprint, 3D envelope, MPN — always absent until S2) and the number of instances using the lineage.
- `Index`: entries plus their folded text and the `Vocabulary` (latest field revisions and their quantity kinds). `search` and `facets` run over it; `inspect` reports one revision with its revisions, symbols, implementations and footprints.
- `synthetic`: original fixture data (`EX-R0603-10K0-F`, `EX-C0402-100N-16V`, `EX-HDR-1X2-001`, …) for tests, the benchmark and trying the palette. It is not a starter library.
- **Deviation from the proposal:** the RKM pre-pass lives in `catalog` (`catalog::rkm`), not in `quantity`, so property entry is unchanged in S1. It is a pure function over a `UnitSet` and can move to `quantity` if property entry adopts it.

**Engine.** `Query::Search { query, limit?, include_drafts? }` (`library.search`), `Query::Facets` (`library.facets`) and `Query::InspectLineage { lineage, revision? }` (`library.inspect`) go through `Engine::query_with(query, &CatalogContext)`; `Engine::query` passes an empty context. Parse errors are `invalid_input` with the term in the message. Queries change neither the document, its revision nor history. CLI `stdio` and MCP reach them through `project.query`, with generated schemas.

**Desktop.**

- **Place palette** (Schematic; the ribbon's Place or the P key, which does nothing while a popup is open): a floating search sheet adapted from Solidcraft's command search, with its edge-to-edge key-hint footer. Type to search; ↑/↓ move; Enter places the highlighted revision with `component.place`, one undo step, at the free 5 mm grid point nearest the view centre whose symbol bounds (body and pin ends plus a 2.5 mm margin) clear every drawn symbol and stay inside the visible canvas, which excludes the Browser and properties cards; Shift+Enter places and keeps the palette open; clicking a row picks it for the Place tool (click the sheet to place); Esc closes. A row whose component has no symbol unit keeps the palette open with "… has no symbol to place." and places nothing; the footer drops the Enter hints whenever nothing can be placed. Each opening and each new query starts the list at the top with the highlighted row in view. Rows show the name with the first matching free-text term highlighted, key field values, the package, `project rN` and four separate badges (`sym`, `fp`, `3D`, `—MPN`); only the highlighted row takes the accent, hover is a neutral wash. Parsed chips and "N hidden" sit under the field (the row is omitted when empty); parse errors and "No component matches." are inset like the group captions. The properties card previews the highlighted row from `library.inspect` (revision, fields, symbol, package envelope, footprint pads, provenance). Recent picks rank higher for the session; they are not persisted until S3. Placed parts take the next free designator under their component's prefix (R1, C1, J1, …), which the core assigns.
- **Browser filter:** a compact search field (zoom icon, proportional text, clear button; Esc clears a non-empty filter) under Components keeps the `library.search` matches (drafts included) in rank order. The Components count reads "shown of all" while a filter is active, so it is visible from every workspace. A text that does not parse shows its error in the palette's error look and keeps the rows of the last text that did. More than 500 matches show the best 500 with "Showing the best 500 of N matches". Both fields bound their text to the core's 512-byte limit, so multi-byte units such as Ω count by bytes.

**Evidence.** Core unit tests cover `4k7`, `4.7k`, `R47`, `4R7`, `4n7` and `100nF`, `R` only where the unit set declares it, `V>=10k` (also through the engine and JSON), unit-key and field-name-key readings, key resolution that does not change when a field named `Voltage` or `Rated power` exists, unknown, ambiguous and reserved keys, ranges, tolerances, filters, ranking determinism under shuffled input with every tier and boost, facets, hidden drafts and `library.inspect`. An automation test runs search, facets and inspect through JSON, compares them with direct engine queries, places the found revision through `project.apply` and checks the `used` boost. Desktop tests drive the palette (type, ↓, Enter → `component.place`, undo; Shift+Enter twice with non-touching symbol bounds; clicking a row arms Place and one sheet click places once; a row without a symbol keeps the palette open; inline error; Esc), the Browser filter (rank order, "n of 24", the last good rows under an error, Esc clears) and multi-term highlighting.

**Performance** (measured 30 October 2026, macOS arm64, Apple Silicon, `--release`, ignored test `catalog::tests::bench_search_on_synthetic_entries`, 60 runs per query, parse included):

| Entries | Index build | Memory (approx.) | Slowest query p95 | Target |
| --- | --- | --- | --- | --- |
| 10 000 | 5.9 ms | 7.7 MB | 0.78 ms (`10k`) | — |
| 50 000 | 23.8 ms | 38.3 MB | 3.85 ms (`10k`) | ≤ 10 ms p95; ≤ 100 MB |

These measure core `search` over a prebuilt index. `Engine::query` rebuilds the project's index on every call, which is cheap at project scale; folder indexes (S3) will be built once and cached. Cold build and rescan targets for 10 k revision files belong to S3 and are not measured.

**Limits.** One source (the project). No Part, MPN, shelves, tags, favourites, lifecycle, health or folders yet. Case folding is lower-casing with µ/μ unified, not full Unicode NFKC. Facets are reported by `library.facets` but not yet shown as clickable filters in the palette.
