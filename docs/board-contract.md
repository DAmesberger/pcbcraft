# Board contract: design rules, net classes, copper fills and board shape

This is the contract slice for four founder requests: configurable manufacturing parameters with profiles for different production specifications, net classes, full copper fills, and board cutouts with a flexible board shape. The board shape uses the parametric sketch, and components can be placed relative to any board edge. The contract defines the types and interfaces that eight parallel tasks build on. Bodies are minimal: they are correct, or they return an explicit `unsupported` error. `tests/board_contract.rs` pins the contract.

## Invariants every task keeps

- **Defaults equal today's values.** `DesignRules::default()` (the built-in profile `pcbcraft-default`, "Pcbcraft default") equals the former hard-coded limits: 0.2 mm copper clearance, copper anywhere inside the board (edge clearance 0), 0.25 mm drill-to-copper and hole-to-hole, 0.1 mm annular ring and min drill, 0.05 mm mask expansion, 0.1 mm mask web and silk width, 0.6 mm silk text height, 0.3/0.6 mm tented vias, a 0.3 mm route width and the land-estimator margins. The test `default_rules_equal_the_former_hardcoded_limits` pins this. When a check moves from a constant to a rule, keep the constant's value in the default and switch the call site to the rule. A test with an old hard-coded expectation keeps passing under the default profile, or it is changed with a justification.
- **One typed engine.** The new operations are `Operation::Rules`, `Operation::Fill` and `Operation::Board`. The new queries are `rules.effective`, `rules.profiles`, `rules.preview_profile`, `board.shape` and `fill.status`. They are served by `pcbcraft_core::schemas()`, so CLI and MCP get them through the existing generic `apply`/`query` tools. Every command is one undo step and leaves the document unchanged on failure.
- **Pre-release format.** The new `Project` fields are serde-defaulted and skipped when empty or default, so existing files and the showcase serialize unchanged (`existing_documents_do_not_mention_the_board_fields`). There are no migrations.
- **Pure core.** Sketch solving runs behind host traits: `FootprintEvaluator` for footprints and the new `BoardShapeEvaluator` for the board. Hosts pass them to `Engine::apply_hosted(rev, op, Evaluators { footprint, board })`. The user profile library lives in `pcbcraft-io`.
- **Clean room.** Built-in profiles are generic, original estimates labelled `ProfileBasis::Estimated`. Fabricator numbers enter only as user profiles, `ProfileBasis::FabricatorEntered`, with source, URL, date and notes.

Validation hooks: `validate::project` checks identity allocation for fills, keepouts and constraints, and runs `Project.rules.validate()`. `layout::validate` calls `fill::validate` and `outline::validate`; these check structure only. A fill whose net is gone, or a constraint whose edge or target is gone, is a check finding (`fill.net_missing`, `board.constraint_unresolved`), not an invalid document.

## Parallel tasks and the files each owns

Shared files take additive edits only: `lib.rs`, `model.rs`, `layout.rs`, `commands/mod.rs`, `validate.rs`, `issues/rules.rs` and `xtask/src/core_modules.rs`. A new core module, or a new dependency edge between modules, changes `xtask/src/core_modules.rs` and the module map in `docs/component-model.md` together. The concurrent via-scaling slice (via2) rewrites `crates/solidcraft-integration/src/project.rs` and the pairwise clearance loops in `layout/copper.rs` and `layout/via.rs`. Check edits there should only change where limits come from (pass rules in); keep `project.rs` hooks small.

1. **rules**: rules core. Owns `rules.rs`, `rules/builtin.rs` and `rules/tests.rs`. Builds on the bounds already there: refines values, adds rule categories if needed (append keys, never renumber), handles profile-switch override handling and edge cases of the `rules.preview_profile` impact, and the CLI-facing schema docs. Defaults stay equal to today's values.
2. **netclass**: net classes. Owns `rules/netclass.rs` and new `apps/pcbcraft/src/pcb_editor/net_classes.rs` (the Net classes panel). Adds the net-class column in `apps/pcbcraft/src/schematic_editor/net_card.rs` and the PCB net card, and routing defaults: the Route tool takes `ProjectRules::track_width(class)` and `via_size(class)` in `apps/pcbcraft/src/pcb_editor.rs`, and `layout::route`/`via` refuse widths below the class or rule minimum. Decides how assignments follow net merges (today the surviving net keeps only its own assignment).
3. **checks**: checks and estimators consume `Project.rules`. Owns `layout/copper.rs`, `layout/via.rs` and `layout/courtyard.rs` (the rule-source edits only; coordinate with via2), `library/footprint/checks.rs`, `library/samples.rs`, `commands/templates.rs` (a rules argument, with the default profile in library context) and `issues/*` texts that name rule, value and source ("Needs 0.15 mm (Fine 4/4: min mask web)"). Includes tests that a profile or class change flips a verdict. Board-edge and cutout clearance read `Project::board()`.
4. **rulesui**: Design rules UI and the profile library. Owns new `apps/pcbcraft/src/pcb_editor/rules_panel.rs`, the Board card entry in `apps/pcbcraft/src/pcb_editor/board_card.rs`, new `crates/io/src/rule_profiles.rs` (atomic, bounded `ProfileFile` JSON files in `UserDirs::config/rule-profiles/`: list, save, rename, delete, import, export) and the CLI `rules-profile list|import|export` in `apps/pcbcraft-cli`. Previews before switching with `rules.preview_profile`, then commits with `rules.set_profile` as one undo step. Adds "Show rule" from Issues.
5. **fillcore**: copper fill computation. Owns `layout/fill.rs` (`compute`, incremental `inputs_key`, island and thermal logic, fill checks) and `model/fill.rs`, plus connectivity through fills in `layout` airwires (an additive hook). Picks a permissive polygon crate after `cargo xtask licences`. Refills stale fills on load in `pcbcraft-io` or the app, off the UI thread. Includes a large-board performance test.
6. **fillview**: fills in the views. Owns new `apps/pcbcraft/src/pcb_editor/fill_card.rs` and `fill_tool.rs`, fill drawing in the PCB 2D painter (`pcb_editor*.rs`, additive), and native 3D fill copper in `crates/solidcraft-integration/src/project.rs` (a minimal hook, after via2) or a new `crates/solidcraft-integration/src/fill.rs`. Updates the showcase in `layout/showcase.rs`: a bottom GND pour and an inner plane with stitching vias.
7. **outline**: board shape core. Owns `layout/outline.rs`, `model/board.rs` and the `BoardShapeEvaluator` implementation in new `crates/solidcraft-integration/src/board.rs` (on the footprint `SketchEvaluator` machinery). Makes the laminate follow `Project::board()` in the 3D board build (a minimal `project.rs` hook), resolves edge constraints (updating `Placement` positions when the sketch re-solves) and reports constraint findings.
8. **outlineui**: board shape UI. Owns new `apps/pcbcraft/src/pcb_editor/board_shape.rs` (a Board shape mode that reuses the footprint sketch tools under `apps/pcbcraft/src/footprint_editor*`), the placement-constraint UI on the component card and board parameters on the Board card. Passes `Evaluators { board: Some(&SketchBoardEvaluator), .. }` through the app's apply path.
