## Implemented boundaries

Six packages plus checks: the pure electronics core (document, typed operations, the one engine), file I/O and recovery, the native Solidcraft adapter, headless automation (JSON lines and MCP), the desktop app and the CLI; `xtask` enforces their layering and the UI container rule. Every document change from the UI, CLI and MCP is a typed core operation. Transactions validate a candidate before commit, reject stale revisions and share one undo history whose entries share unchanged data. Definition drafts are engine state: each finished draft edit is one undoable `library.edit`, and drafts are saved and recovered with the project. Since 30 October 2026 the document follows slices 1–3 of the [component model](component-model.md): components, symbols, packages, footprints, bindings, quantity kinds and fields are separate revisioned definitions, instances pin one exact component revision, each symbol unit is a separate occurrence, instance values are typed overrides of the fields the pinned component selects, and terminals declare function arrays that each instance selects from, with ERC using the active function. Since 1 November 2026 the desktop authors multi-function pins, peripherals and Rhai pin rules in the Pins tab and assigns peripherals in the schematic pin-mux panel ([pin functions](#pin-functions-c1c7)).

- **Components:** the desktop authors a working set of five drafts (component, symbol, package, footprint, binding): electrical terminals and a drawn symbol (the Symbol tab's ribbon has Select, Draw — line, polyline, rectangle, rounded rectangle, circle, arc, polygon, multi-line text —, Pins — pin, field —, Arrange — rotate, mirror, duplicate, delete — and Grid/Snap tools with snapping, box selection and per-selection properties, rounded corners and several units; see [G2](component-model.md#symbol-drawing-g2); the view draws the core-resolved unit with the designator placeholder and working-binding pin numbers), package terminals, rectangular pads, datum/model offsets and explicit package-terminal mappings. One electrical terminal can map to multiple package terminals/pads. Passive/connector templates work, and Publish sends one `library.publish` of all five, so unchanged siblings also get new identical revisions. Existing instances retain exact revisions. Multi-unit symbols, unit placement and unused/no-connect decisions are available through the engine, CLI and MCP; the desktop shows unit states read-only. Starting a component in a project with no drafts takes six undo steps (five reservations and one edit).
- **Schematic:** since 2 November 2026 several sheets with a hierarchy, net labels (local, global, hierarchical), power ports, sheet furniture with page frames and title blocks, annotation across sheets, label/hierarchy/power ERC and vector PDF printing; see [schematic capture](schematic-capture.md). Per sheet: find components in the Place palette (`library.search`, see [parts library S1](#parts-library-s1)) and place exact revisions (`component.place`; the core numbers each new instance under its component's designator prefix, R1, R2, C1, …), draw every symbol occurrence from its core-resolved graphics, pins, pin names and numbers and text (upright rule; picking through the core hit test; see [graphics G1b](component-model.md#drawable-symbol-graphics-g1a-g1b)), edit the designator and, as text parsed in core, the typed fields the component shows on the symbol (`instance.set_properties`, with the parser's rejection shown inline), occurrence placement and move snapped to the 2.5 mm symbol grid, rotate (Cmd/Ctrl+R) and left-to-right mirror (Shift+X) of the selected occurrence from the keys, the ribbon's Arrange group or the Rotation/Mirror properties (`symbol.orient_unit`, one undo step; wires follow the pins and text stays upright; a unit cannot yet be turned before it is placed), wiring between terminals and onto other wires (a wire end landing on a segment splits it at a junction in one `schematic.connect` step; `schematic.connect` targets a terminal, a junction or `{wire, at}`), disconnection (a junction left with one wire goes with its stub), persistent net IDs with editable names, and a basic electrical-check subset. Wires draw horizontal-first; a plain crossing does not imply a connection. A solid dot, derived from connectivity and scaled with zoom, marks every point where three or more conductors meet (a pin counts as one); a wired pin end has no ring, an unconnected one shows the Issues to-do ring and a no-connect a cross. Both marks are sized from the pin text (`schematic::PIN_RING_MM`, `NO_CONNECT_MM`; the ring's diameter is 0.8 of the pin text height) and the ring sits just outside the pin end, so the pin line stops at its edge; the PDF draws the same cross. The Wire tool snaps the pointer to the nearest pin end, junction, label or sheet pin within 12 screen pixels at any zoom, or to a pin's connection end when the pointer is on its drawn line, and marks exactly where the end will land with an accent ring and dot. Connecting merges nets (routed, else older, ID survives); disconnecting splits them (larger group keeps the ID). Direct edits that change a routed net's membership are rejected; the update planner keeps copper on nets that only gain terminals and lists copper on shrunk, removed or merged-away nets for explicit removal.
- **SVG import (F-SVG):** Import SVG… on the Symbol tab's Draw group and the Footprint tab (silkscreen or assembly) adds an SVG drawing as editable lines, arcs, circles, rounded rectangles and filled or outlined polygons at the view centre, with a scale, as one undo step; the CLI and MCP have `library.import_svg`. Béziers are flattened within 0.01 mm by default; filled regions with holes import as outlines and text is skipped. See [SVG import](component-model.md#svg-artwork-import-f-svg).
- **Footprints (F1/F2):** typed pads of every kind and shape, holes, vias, mask/paste rules and footprint graphics, edited on the Component Footprint tab and drawn in PCB 2D and native 3D from one core pad geometry; parametric footprints through `library.edit_footprint` and the Solidcraft-sketch evaluator (desktop, CLI and MCP). See [F1/F2 as built](component-model.md#footprint-geometry-editing-and-3d-f1f2-as-built).
- **Footprint sketching and templates (F4/F5):** on an empty or parametric footprint the Footprint tab's ribbon leads with Pads (from template, template pads, custom, row/dual-row/quad/grid arrays, drill, slot) and Constrain (dimension, geometric constraints, all dimensions), then Publish, Sketch (select, line, arc, circle, rectangle) and Layer (construction, silkscreen, assembly, courtyard). Pads are sized by named parameters; dimensions are drawn on the canvas, edited in place and can define and bind a parameter (`len = 2.5 mm`); constraint glyphs and solver colours show free and conflicting geometry; free points drag with a live solve; a parameters panel lists values and readers. - **PCB:** explicit additive schematic sync preview, move/rotate/flip/lock placements, continuous interactive routes (45°, 90° and free elbows, Backspace unwinding, layer changes through a via, width and via presets) and atomic routing edit sets, track locks/deletion, airwires from physical copper islands, basic edge/clearance checks on the exact pad outlines, courtyard overlap between same-side parts and net highlighting. - fabrication presets: every look of every fabrication combination is a valid Solidcraft surface; saved bodies look the same for every fabrication; the mask table, hue and show-through order; finish roughness; a non-default fabrication restyles only the mask and finish layers; `layout.set_fabrication` through the engine (undo, redo, stale revision, save/reopen, unknown values and a file without the attributes refused), through JSON and in the schemas; and the Soldermask row issuing the operation;
- byte layout, the size cap, the parts prefix and shadow counts; recolour-only highlighting; the background repack;
- fit in wide, narrow and very wide views from four directions; zoom keeps the anchor under the pointer; perspective picking.

Limits:

- **Renderer:** the product look comes from the `pcbcraft-product-look` branch of the DAmesberger/solidcraft fork (see [development notes](development.md) for the pinned revision); upstream Solidcraft does not have it. There are no cast shadows from the key light (contact decals and ambient occlusion stand in). The studio has no floor-facing softbox, so the board's underside relies on direct lights. Colour-only fabrication changes still rebuild the native model.
- **Pictures:** evidence pictures come from the viewport's own frame drawn headless through Solidcraft's renderer (`viewport/pictures.rs`), not from window captures.
- **Not modelled:** no 3D silkscreen yet (footprints carry silkscreen graphics and 2D Layout draws them; the native legend layer is G5), no bare-laminate ring inside mask openings, no body edge chamfers or edge plating; the glass weave is procedural (no cut yarn ends). Track copper ends square under round mask caps.
- **Terminations:** placed by package rules from the package's declared body: `chip_resistor` and `chip_capacitor` get wrapped end terminations (the resistor also its overcoat), `moulded` packages lead bands.
- **Drills in the native model:** the laminate slabs' holes and the vias use fixed board positions while pad copper follows the placement parameters, so moving a part inside Solidcraft separates its copper from its holes until Sparksmith regenerates the model. Each via is a fixed translation of its size's definition: the per-via `via_{id}_x`/`_y` parameters of earlier builds are gone, a trade-off for building thousands of vias; the board outline still follows `board_width` and `board_depth`.
- **Camera:** the 3D view is perspective, which changes fit and zoom feel compared with the earlier orthographic view.

## Copper fixture and performance boundary

The copper sample (an adapter test fixture since the restructuring, no longer a workspace) has seven semantic items: connected top traces, a pad, a plated via with empty drill, a disconnected same-net island, a zone with a hole and a bottom trace. Tests cover volumetric geometry, depth-aware picking, source metadata, width edits, undo/redo and native regeneration. Selection/view changes preserve mesh `Arc` identity and the scene-build counter; GPU scene blocks reuse vertex bytes when only the palette changes.

The live 3D model is made on a worker: while editing in PCB 2D the model is prepared in the background 350 ms after the last edit, and an open PCB 3D view asks for it at once. Since stage A4 (13 November 2026) the live model is the direct mesh only: the board's flat bodies are meshed from the board plan and each part is its package revision's own Solidcraft design, and every next board (an edit, an undo, a refill) is made from what the last model kept (`project::update`); no native design of the board is built for the view and no earlier model is kept for undo. The exact native build runs only for export and as the parity reference ([3D speed profile](3d-speed-profile.md)). The measurements that follow are of the exact native build, before A4. Measured on one shared 18-core machine ([PCB realism](pcb-realism.md#build-cost-measured)): the 10,000-via benchmark board (about 260 round-capped tracks) builds in about 2.8 s; with the layout's 2,000 tracks it builds in 8.5 s (about 3 ms a track, the 3 s target not met there); moving a via on it updates in 2.0 s and moving a part in 0.4 s; opening PCB 3D on a finished 10,000-via build draws the first frame in about 0.1 s offscreen and in 8–37 ms in the running app (vias instanced, 6.1 M triangles). These are measurements of the benchmark boards, not a general large-board claim. Envelope definitions are still separate per instance; the 100k benchmark and local cache invalidation remain open (courtyard checks still compare pairs up to their own limit). Current safeguards bound the layout to 2,000 tracks, 4,096 placed pads and 16,384 vias. The copper, via and routing checks file shapes in a uniform grid by their bounds and compare only shapes within the largest rule of each other, so every via of a 10,000-via, 2,000-track board is checked (the copper graph builds in about 7 ms and the board checks, graph included, take about 33 ms, measured; see [one copper graph](copper-graph.md#slice-1-as-built)); copper piled on copper stops them at 1,000,000 nearby pairs, or the copper graph at four joints per element, with an explicit incomplete-check message.

## High-speed routing

## Remaining release work

The initial editors are intentionally narrow: traces and through vias only (board checks and copper connectivity use each pad's exact outline, with curved edges flattened within 2 µm); PCB 2D draws every copper layer and the board vias, routes through a via with V and places vias with the Via tool, but has no stackup editor (stackups are set through commands, the CLI or MCP); board builds grow about linearly with vias (measured in [PCB realism](pcb-realism.md#build-cost-measured): 10,000 vias build in about 3 s, and the 3D view shows them instanced in about 0.1 s); the 3D model is prepared in the background while the board is edited in 2D; manual routes; electrical and clearance checks against the board's fab profile, which the user imports or writes from a fabricator's published capabilities. One fill of a 200 × 200 mm plane over 10,000 through vias took 1.40 s in a release build (macOS arm64). Copper fills are authored with the Fill tool (outline with arcs), edited through the Fill card and outline handles, drawn in PCB 2D (solid, hatched or outlines only) and built in PCB 3D as saved copper under the display-only mask (an inner fill in its own foil level of the laminate); their copper is computed by the fill core (`fill.refill`), and the showcase carries a bottom ground pour and an inner ground plane with stitching vias. No manufacturing-ready DRC claim follows from zero basic-check messages.

Still pending: drawing tools for graphics on a footprint with explicit pads (a sketched footprint draws them with the sketch tools; explicit ones are edited through `library.edit_graphics`; symbol drawing is [G2](component-model.md#symbol-drawing-g2)), trim, fillet, offset, split and mirror sketch edits and the land calculator (F6), native model-history composition and reusable model assets, multi-sheet hierarchy, net-label tools, junction dragging, blind/buried vias, rule regions, PCB 2D stackup editing, solder joints in 3D, manufacturer catalogs/import and manufacturing output. On macOS, Dock › Quit (and a logout) still ends the app without the unsaved-work prompt: winit's application delegate has no `applicationShouldTerminate:`, and Sparksmith forbids the `unsafe` code that would add one. The exit writes the latest edit to the recovery snapshot instead, which the next launch offers. ⌘Q, the app menu's Quit and the window close button ask Save, Don't Save or Cancel ([e2e UI run, finding 3](e2e-ui-run.md)). Solidcraft's camera navigation and app shell are private upstream, so Sparksmith reproduces the default navigation bindings and rebuilds the ribbon/card helpers from public tokens and containers. Push-and-shove and walkaround routing are built ([push-and-shove](push-and-shove.md)), with measured per-move timings on the showcase and a 10,000-via board; Select drags an existing track segment with shove (`layout.track_drag`), corner drags are not built.
