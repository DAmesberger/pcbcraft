## Implemented boundaries

Six packages plus checks: the pure electronics core (document, typed operations, the one engine), file I/O and recovery, the native Solidcraft adapter, headless automation (JSON lines and MCP), the desktop app and the CLI; `xtask` enforces their layering and the UI container rule. Every document change from the UI, CLI and MCP is a typed core operation. Transactions validate a candidate before commit, reject stale revisions and share one undo history whose entries share unchanged data. Definition drafts are engine state: each finished draft edit is one undoable `library.edit`, and drafts are saved and recovered with the project. Since 30 October 2026 the document follows slices 1–3 of the [component model](component-model.md): components, symbols, packages, footprints, bindings, quantity kinds and fields are separate revisioned definitions, instances pin one exact component revision, each symbol unit is a separate occurrence, instance values are typed overrides of the fields the pinned component selects, and terminals declare function arrays that each instance selects from, with ERC using the active function. The desktop authors one fixed function per terminal; multi-function authoring and selection are reachable through the engine, CLI and MCP only.

- **Components:** the desktop authors a working set of five drafts (component, symbol, package, footprint, binding): electrical terminals and a drawn symbol (the Symbol tab's ribbon has Select, Draw — line, polyline, rectangle, rounded rectangle, circle, arc, polygon, multi-line text —, Pins — pin, field —, Arrange — rotate, mirror, duplicate, delete — and Grid/Snap tools with snapping, box selection and per-selection properties, rounded corners and several units; see [G2](component-model.md#symbol-drawing-g2); the view draws the core-resolved unit with the designator placeholder and working-binding pin numbers), package terminals, rectangular pads, datum/model offsets and explicit package-terminal mappings. One electrical terminal can map to multiple package terminals/pads. Passive/connector templates work, and Publish sends one `library.publish` of all five, so unchanged siblings also get new identical revisions. Existing instances retain exact revisions. Multi-unit symbols, unit placement and unused/no-connect decisions are available through the engine, CLI and MCP; the desktop shows unit states read-only. Starting a component in a project with no drafts takes six undo steps (five reservations and one edit).
- **Schematic:** single sheet, find components in the Place palette (`library.search`, see [parts library S1](#parts-library-s1)) and place exact revisions (`component.place`; the core numbers each new instance under its component's designator prefix, R1, R2, C1, …), draw every symbol occurrence from its core-resolved graphics, pins, pin names and numbers and text (upright rule; picking through the core hit test; see [graphics G1b](component-model.md#drawable-symbol-graphics-g1a-g1b)), edit the designator and, as text parsed in core, the typed fields the component shows on the symbol (`instance.set_properties`, with the parser's rejection shown inline), occurrence placement and move snapped to the 2.5 mm symbol grid, rotate (Cmd/Ctrl+R) and left-to-right mirror (Shift+X) of the selected occurrence from the keys, the ribbon's Arrange group or the Rotation/Mirror properties (`symbol.orient_unit`, one undo step; wires follow the pins and text stays upright; a unit cannot yet be turned before it is placed), two-terminal wiring, disconnection, persistent net IDs with editable names, and a basic electrical-check subset. Crossed wires do not imply a connection. Connecting merges nets (routed, else older, ID survives); disconnecting splits them (larger group keeps the ID). Direct edits that change a routed net's membership are rejected; the update planner keeps copper on nets that only gain terminals and lists copper on shrunk, removed or merged-away nets for explicit removal.
- **SVG import (F-SVG):** Import SVG… on the Symbol tab's Draw group and the Footprint tab (silkscreen or assembly) adds an SVG drawing as editable lines, arcs, circles, rounded rectangles and filled or outlined polygons at the view centre, with a scale, as one undo step; the CLI and MCP have `library.import_svg`. Béziers are flattened within 0.01 mm by default; filled regions with holes import as outlines and text is skipped. See [SVG import](component-model.md#svg-artwork-import-f-svg).
- **Footprints (F1/F2):** typed pads of every kind and shape, holes, vias, mask/paste rules and footprint graphics, edited on the Component Footprint tab and drawn in PCB 2D and native 3D from one core pad geometry; parametric footprints through `library.edit_footprint` and the Solidcraft-sketch evaluator (desktop, CLI and MCP). See [F1/F2 as built](component-model.md#footprint-geometry-editing-and-3d-f1f2-as-built).
- **Footprint sketching and templates (F4/F5):** on an empty or parametric footprint the Footprint tab's ribbon leads with Pads (from template, template pads, custom, row/dual-row/quad/grid arrays, drill, slot) and Constrain (dimension, geometric constraints, all dimensions), then Publish, Sketch (select, line, arc, circle, rectangle) and Layer (construction, silkscreen, assembly, courtyard). Pads are sized by named parameters; dimensions are drawn on the canvas, edited in place and can define and bind a parameter (`len = 2.5 mm`); constraint glyphs and solver colours show free and conflicting geometry; free points drag with a live solve; a parameters panel lists values and readers. Family templates (chip, SOIC/SOP, QFN/DFN with exposed pad, pin header/DIP) build into an empty draft with explicit derived courtyard and assembly roles (`library.footprint_from_template`, also CLI and MCP). Each gesture or form is one undo step. Lint adds silk width and text height; boards check courtyard overlap. See [F4/F5 as built](component-model.md#footprint-sketch-ui-and-templates-f4f5-as-built).
- **Library folders (S3):** local folders of immutable revisions (plain files, shareable through git) are added, created, rescanned and turned on or off as per-user sources; the Place palette searches them after the project, places through `library.place_from` (import and place, one undo step) and marks update-available and modified sources; components are promoted to a writable folder and duplicated; favourites and recents persist per user. Imported revisions keep their origin and packed assets, so a project reopens without its folders. CLI and MCP have the same requests. See [S3 as built](parts-library.md#s3-as-built).
- **PCB:** explicit additive schematic sync preview, move/rotate/flip/lock placements, manual two-click routes and atomic routing edit sets, track locks/deletion, airwires from physical copper islands, basic edge/clearance checks on the exact pad outlines, courtyard overlap between same-side parts and net highlighting.
- **Native models:** substrate, physical 35 µm pads (every pad shape, plated barrels through the laminate)/traces, package envelopes, parameter-driven positions/angles/dimensions and rigid top/bottom joints. Export uses the captured electronics project, regardless of the active editor. Generated model source metadata retains instance/pad/track/net/layer identities. Background preview results are checked against request identity and current project/draft before display.
- **Persistence:** `.pcbcraft` files (format version 1, pre-release, no migrations) include the revisioned library snapshot, instances, symbol occurrences, mappings, nets and drafts, with bounded reads and atomic replacement. Other versions, unknown fields and damaged references are rejected without changing the current project. File dialogs, saves, opens and exports run off the UI thread; unsaved work is written to a recovery snapshot and offered at the next launch. `.solidcraft` files are written by the actual engine without STEP or cached-only geometry.

## Photoreal PCB 3D view

30 October 2026, revised after review the same day. The PCB 3D view and the Component 3D preview draw through Solidcraft's PBR path. Native bodies carry the physical look stored in the file; display-only layers use the same table. [Materials](materials.md) gives the values, sources and layer dimensions.

- **What the model shows:**
  - glossy green soldermask drawn as a lacquer (a clear coat over a pigmented body, with orange peel and the glass weave faintly showing through), with round-ended mask caps that show traces as raised, lighter-green lines, interrupted at every mask opening (tracks passing through a land included);
  - ENIG finish over every land and over any track copper inside its mask opening, so no bare copper shows at a track/pad junction;
  - the FR-4 board edge;
  - chip resistors with white alumina sides, a black overcoat, tinned terminations wrapped over both ends, and bright concave solder fillets to the lands; MLCC in tan ceramic; moulded packages with low lead bands. The body style is the package's authored `body`, never the designator.
- **Fabrication presets:** the PCB properties card's Board section has Soldermask (green, blue, red, purple, yellow, black, white, clear), Mask finish (gloss, satin, matte), Pad finish (ENIG, HASL tin-lead, lead-free HASL, OSP, immersion silver) and Silkscreen (white, black, yellow) rows. A change applies `layout.set_fabrication` as one undo step; the attributes are saved in the `.pcbcraft` design and reach the CLI and MCP through `project.apply`. The 3D model rebuilds with the mask and finish looks in [materials](materials.md#fabrication-presets); the saved `.solidcraft` model is unchanged. Silkscreen colour is stored but not drawn (no legend graphics yet). `fabrication` is a required field of the one pre-release format, so `.pcbcraft` designs and recovery entries saved before it existed are refused on open; that is expected, not a bug. Restating the current attributes is a no-op (no revision, no undo step).
- **Saved model:** only physical bodies (laminate, copper, envelopes) are native. They are disjoint except copper joining copper, so interference checks and mass properties of the saved file are physical. Display layers are meshes built on the worker and never saved.
- **Identity:** every native body kind is recorded in the native metadata (`org.pcbcraft.electronics.bodies.N`, measured as serialized so escaped names stay below Solidcraft's 64 KiB value limit). Mask caps and finish strips pick as their track; terminations, overcoat and solder as their part.
- **Lighting:** a perspective camera (0.5 rad field of view) and Solidcraft's opt-in product look: a procedural studio environment fixed in the world (baked once on a worker thread, about 80 ms, and installed into the renderer, so the window never waits), which metals and the mask's lacquer reflect, so highlights slide across the board when it is orbited; PBR Neutral tone mapping with dither (no banding; under 0.03 % of pixels reach white in any evidence picture); ambient occlusion on the studio's light. Key, fill and rim turn with the camera; four floor-bounce lights stay fixed so vertical metal reads; from below, stronger direct lights and an ambient light make up for the studio's dark floor. Values and reasons: [materials](materials.md#pcb-3d-look).
- **Surface detail:** the FR-4 glass weave (style 7628: continuous warp and weft bundles with filament striations) under clear mask and faintly under translucent colours, and at a quarter of that swing on routed edges; a long, shallow orange peel on every mask, so a gloss mask's softbox reflection keeps its shape. Patterns fade to their mean before they can alias; relief fades out toward grazing views.
- **Navigation:** Fit frames the eight corners of the model's box in both the vertical and the horizontal field of view with an 8 % margin, using the view's real aspect (fitted again on the first draw and when the first model arrives). Scroll zooms toward the surface under the pointer; right-drag orbits about the surface point under the pointer.
- **Shadows, AA and background:** a soft ground shadow and per-package contact shadows; 2× supersampling once the view settles; a neutral gradient background that follows the theme.
- **Selection and uploads:** highlight is recolour-only (cached flat blocks per pick identity in the highlight slot; blocks indexed by a hash map on the worker). The worker packs one PBR buffer, parts first and board after, which moves into the viewport's slot without a copy and is not kept twice. Hide substrate repacks on a background thread; shadows and selection change at once.
- **Stale models:** while a newer model builds, the last model of the same kind stays up under an "Updating 3D model…" note, and clicks on it are ignored.
- **Status messages:** errors now fade after 12 s and clear on a workspace change, as well as on the next successful action.

Limits:

- **Renderer:** the product look comes from the `pcbcraft-product-look` branch of the DAmesberger/solidcraft fork (see [README](../README.md) for the pinned revision); upstream Solidcraft does not have it. There are no cast shadows from the key light (contact decals and ambient occlusion stand in). The studio has no floor-facing softbox, so the board's underside relies on direct lights. Colour-only fabrication changes still rebuild the native model.
- **Pictures:** evidence pictures come from the viewport's own frame drawn headless through Solidcraft's renderer (`viewport/pictures.rs`), not from window captures.
- **Not modelled:** no 3D silkscreen yet (footprints carry silkscreen graphics and 2D Layout draws them; the native legend layer is G5), no bare-laminate ring inside mask openings, no body edge chamfers or edge plating; the glass weave is procedural (no cut yarn ends). Track copper ends square under round mask caps.
- **Terminations:** placed by package rules from the package's declared body: `chip_resistor` and `chip_capacitor` get wrapped end terminations (the resistor also its overcoat), `moulded` packages lead bands.
- **Drills in the native model:** the saved `Drills` cut uses fixed board positions while pad copper follows the placement parameters, so moving a part inside Solidcraft separates its copper from its holes until Pcbcraft regenerates the model.
- **Camera:** the 3D view is perspective, which changes fit and zoom feel compared with the earlier orthographic view.

## Copper fixture and performance boundary

The copper sample (an adapter test fixture since the restructuring, no longer a workspace) has seven semantic items: connected top traces, a pad, a plated via with empty drill, a disconnected same-net island, a zone with a hole and a bottom trace. Tests cover volumetric geometry, depth-aware picking, source metadata, width edits, undo/redo and native regeneration. Selection/view changes preserve mesh `Arc` identity and the scene-build counter; GPU scene blocks reuse vertex bytes when only the palette changes.

No large-board speed claim is made. Current native construction rebuilds the project in a worker; it is not incremental or cancellable within a build. It creates separate envelope definitions per instance, although the earlier native fixture proves shared definition reuse. The 1k/10k/100k benchmark, GPU draw/upload metrics, spatial indexing and local cache invalidation remain open. Current safeguards bound the layout to 2,000 tracks and 4,096 placed pads, and stop pair checks at 100,000 comparisons with an explicit incomplete-check message.

## Remaining release work

The initial editors are intentionally narrow: traces only (board checks and copper connectivity use each pad's exact outline, with curved edges flattened within 2 µm); two copper layers; fixed 1.6 mm substrate and 35 µm copper; manual routes; basic electrical/clearance checks. The copper sample's vias and zone cannot yet be authored in the PCB editor. No manufacturing-ready DRC claim follows from zero basic-check messages.

Still pending: drawing tools for graphics on a footprint with explicit pads (a sketched footprint draws them with the sketch tools; explicit ones are edited through `library.edit_graphics`; symbol drawing is [G2](component-model.md#symbol-drawing-g2)), trim, fillet, offset, split and mirror sketch edits and the land calculator (F6), native model-history composition and reusable model assets, multi-sheet hierarchy, junction/net-label tools, configurable stackup/rules, vias/pours, manufacturer catalogs/import and manufacturing output. On macOS, Cmd+Q quits without the unsaved-work prompt (the work survives in recovery); the window close button and File actions do prompt. Solidcraft's camera navigation and app shell are private upstream, so Pcbcraft re-applies the same camera operations and rebuilds the ribbon/card helpers from public tokens and containers. Push-and-shove remains release 2 if absent from release 1; the routing strategy and atomic edit-set boundary are in place, not the solver.
