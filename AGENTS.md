# Sparksmith agent instructions

Sparksmith is PCB design software, written in Rust, with component authoring, schematics, PCB layout and integrated 3D, using Solidcraft's technology and UI conventions. These instructions are adapted from Solidcraft; see [attribution](ATTRIBUTION.md).

## Start here

Read [ROADMAP.md](ROADMAP.md) for the active milestone and [docs/milestone-0.md](docs/milestone-0.md) before foundation work. Product scope is in [docs/sparksmith-plan.md](docs/sparksmith-plan.md); vocabulary is in [GLOSSARY.md](GLOSSARY.md). Distinguish user requirements from proposed scope boundaries in those documents.

The workspace layers are: `sparksmith-core` (pure document, typed operations, the one engine), `sparksmith-io` (atomic files, recovery), `sparksmith-solidcraft` (native 3D via Solidcraft's engine), `sparksmith-automation` (headless session, JSON-lines and MCP transports), and the desktop and CLI apps. `cargo xtask layers` enforces the direction, `cargo xtask core-modules` the module map inside the core ([component model](docs/component-model.md)), `cargo xtask connectivity` that only the copper graph decides whether copper joins ([copper graph](docs/copper-graph.md#where-connectivity-lives)), `cargo xtask generic-terms` that code names a linked design generically, never by an example product, `cargo xtask format-lock` that a stored type does not change without a format version or feature change, `cargo xtask surface` that the command catalog does not change without its module's version ([extension surface](docs/extension-surface.md)), and `cargo xtask board-parity` (added with the board plan) that the live 3D mesh and the exact export build the same bodies from the one board plan ([board plan and interface](docs/architecture/board-plan-and-interface.md)). Run `cargo xtask ci` (inside `nix develop` if Rust is not installed) for formatting, dependency and UI-container boundaries, strict Clippy, native tests and headless wasm compilation. See [development](docs/development.md) for commands and [editor evidence](docs/editor-evidence.md) for current capabilities and limits; scaling benchmarks and complete first-release workflows remain pending.

## Hard rules

- Application code is Rust, with a wasm-compatible core and egui/eframe/wgpu UI. Keep UI and transport dependencies outside the document, electronics geometry and checking layers.
- Reuse Solidcraft's engine for part models, exact construction, STEP and native persistence. Do not introduce a second kernel or a private native-file writer. The board's flat bodies (laminate, copper, drills and films) are prisms of the document's 2D geometry, described once by the board plan. The live 3D view meshes the plan directly; the exact `.solidcraft` board is built from the same plan for export and as the test reference. Neither may add, drop or reshape a body, and `cargo xtask board-parity` holds them together. The saved model keeps the parameters and placement relationships that recompute without Sparksmith. STEP is an optional exchange format.
- Copper is real thickness-aware geometry. Preserve PCB object, net and layer identity through the board plan, rendering, picking and the exported model. Selection and camera changes must not rebuild geometry.
- Another design references a board only through its published interface: datums with ids and slots that survive edits, rebuilds and renames. Link updates in either direction go through a preview bound to both files' revisions and are never silent. A reference that no longer resolves is named in the user's words and blocks publishing to linked designs until resolved.
- Follow the Sparksmith design system (`crates/ui`): shared tokens, containers and navigation. PCB 2D/3D are modes of one design with shared selection, properties and undo.
- Route every design operation through one typed command engine shared by UI, CLI and MCP. Programmatic calls never open dialogs; failed document mutations leave the document unchanged.
- Library identity, explicit pin mapping and exact project snapshots are foundational. Apply library updates through an atomic impact preview; never infer electrical compatibility from matching names.
- Plan routing for push-and-shove from the first implementation; deliver it by release 2 if it is absent from release 1.
- Production Rust uses checked input handling and `Result`; deny application `unsafe`, except in small, documented native-platform modules that have no safe API (as in Solidcraft): each allows it for itself only, and states why. Forbid unchecked `unwrap`, `expect`, panic and unfinished-code macros. Bound input sizes and arithmetic; keep long work off the UI thread. Shared dependency internals retain their upstream policies.
- Preserve work with atomic saves and recovery. Reject unsupported versions and unknown features, naming them, instead of silently dropping them. The file format is versioned: every incompatible change to a stored type raises `FILE_VERSION` and adds a pure step to the converter chain (`sparksmith_io::convert`) and a golden file; an optional capability is a named feature, which a file lists only when it uses it. `cargo xtask format-lock` enforces this. Until the first release the chain runs only as `sparksmith convert` and the app reads only the current version, naming that command when it refuses an older one ([file versions](docs/development.md#file-versions)).
- Sparksmith is MIT OR Apache-2.0. Follow Solidcraft's independent-implementation policy: use public specifications/documentation and permissive code dependencies; do not read, copy, paraphrase or link GPL/LGPL/AGPL code. Do not read or copy KiCad (source or its symbol, footprint and 3D libraries, including CC-BY-SA data), LibrePCB, Horizon EDA, gEDA/Lepton or Fritzing, and take no code, data, text, icons or ids from commercial EDA tools. Part CAD data published for use in other tools (for example manufacturer footprints and STEP models) may be used like a datasheet, with its source and licence recorded. Fixtures are original. Attribute reused code, instructions and assets; preserve their notices. `cargo xtask licences --check` enforces dependency licenses, `cargo xtask brand-crates` keeps SolidCraft's brand-licensed UI crates (and `solidcraft-ui-egui`) out of the dependency graph, since the interface code is vendored in `crates/ui`, `cargo xtask clean-room` rejects EDA library files, and `cargo xtask no-builtin-data` rejects library data compiled into the program (`include_str!`/`include_bytes!` outside tests and its asset allowlist; [generator plugins](docs/generator-plugins.md#gate-no-built-in-data)); reasoning is in [sparksmith-libraries](skills/sparksmith-libraries/SKILL.md#clean-room-sources).
- Verify observable behavior and measured correctness. Label performance targets as targets until measured. Do not weaken expected results to make a test pass.
- Keep changes within the task. Work in an isolated checkout for any Solidcraft changes; honor that checkout's instructions. These rules do not authorize upstream pushes, issues, PRs or publication.
